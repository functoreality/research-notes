## 任务目标

给定一篇论文（arXiv 链接或 PDF），评估其对本笔记系统是否有值得补充的新信息。核心问题是：

> 这篇论文里有没有我的笔记尚未覆盖、但对我的 PDE 基础模型（PDEformer）研究有价值的内容？

## 工具准备

**开始前，必须先阅读 `skills/outline-read/SKILL.md`**，了解 outline-read 工具的完整用法（调用方式、折叠展开、UID 跳转、展开级别等）。后续不再重复这些基础用法。

## 探索流程

### 入口一：主笔记文件名匹配

根据论文主题，选择可能相关的**主笔记文件**（见上表），用 outline-read 浏览。

### 入口二：keyword.md

`keywd.md` 仅 261 行，可全量读取或搜索关键词。

> `keywd.md` 是扁平文件（无 Tab 缩进），不需要 outline-read。

### 入口三：全局搜索

在所有笔记中搜索可能相关的关键词。同一个概念建议中英文各搜一次（或逻辑）；一种语言搜不到就换另一种。

> 使用当前环境可用的搜索工具（如内置 grep 接口或 bash grep），不必拘泥于特定命令。

### 深入探索：UID 链跳转（重要）

找到相关关键词或 `((UID))` 引用后，**必须**用 outline-read `--uid` 跟随链接链。这是笔记系统最核心的导航方式。

典型流程：在 `keywd.md` 搜索关键词找到 UID → `outline-read --uid` 跨文件跳转 → `read` 看周围原文 → 发现新 UID 引用 → 继续跳转 → 重复。

**关键原则**：不要只看 grep 的碎片命中。沿 UID 链跳转才能理解笔记中的完整讨论和上下文关系。

## 评判标准：什么值得关注

我开发的是 **PDE 基础模型 PDEformer**，是通用算法研究者，不是特定应用场景的使用者。

### 核心原则

**笔记中已有相关讨论 ≠ 论文无价值。** 恰恰相反：如果笔记中某个主题有大量讨论（如神经网络架构设计、NO 架构、多方程训练策略），说明这是我重点关注的方向。此时应认真审视：我已有的框架是否完备？当前论文是否提供了可补充的细节、新的视角、或值得对比的替代方案？

### 高优先级（重点关注）

- **有一般性的算法创新**：新的训练范式、架构设计思路、损失函数设计、token 化策略等
- **简洁而有效的方法**：简单 idea 效果好，最值得关注
- **与 PDE 基础模型直接相关**：多方程/多物理联合训练、任务统一化、跨方程泛化、模块组合推理等
- **能补充我已有框架的具体方案**：即使大方向笔记已有覆盖，如果论文提供了笔记中缺失的具体实现细节、架构变体、或实验洞察，也值得记录
- **新的数据集**：论文自己构建且**已公开发布**的 PDE 数据集（非直接用 PDE-bench 等现成资源）

### 中等优先级（视情况报告）

- 有启发性的实验分析或 ablation study
- 对已有方法的深刻洞察或理论分析
- 即使是特定应用，但技术方案有明显迁移价值的
- 与笔记已有工作形成有趣对比的替代方案

### 低优先级（通常可忽略）

- 纯应用工作，技术方案无迁移价值
- 仅做微小改进、无实质新颖性
- 技术细节繁琐、没有让人"眼前一亮"的内容
- 笔记中已有**更深更全**的覆盖，且论文无额外增量信息（注意：仅仅「有相关讨论」不算「更深更全」）

### 关于数据集

值得记录需同时满足两个前提：**自己构造**（非直接用 PDE-bench、FNO 数据集等现成资源），且**确实公开发布**。判断流程：

1. 论文中直接提供了下载链接（或代码仓库链接，仓库内包含数据集下载）→ 可记录
2. 论文中未提供链接，但能在网上搜到明确对应该论文的公开代码仓库（如 GitHub），且仓库内含数据集 → 可记录（注意需核验仓库确实对应此论文，可参考 README、论文标题匹配等）
3. 仅描述了构造方式，论文无链接且网上搜不到对应仓库 → **不记录**

数据集主要记录在 `numeric.md` 中，条目分散（如有些在各方程类型的对应位置）。
找入口建议方式：文件内搜「数据集」，命中后沿周围层级结构定位到合适的子节。浏览建议用 outline-read。

```bash
# 仅为寻找入口，后续探索需 outline-read
grep "数据集" ./raw/numeric.md
```

## 输出格式

审查完成后，输出简洁报告。无需列出「笔记已有覆盖」——这些内容我自己知道，不需要回顾。

```
## 论文概要
[一句话描述论文核心贡献]

## 可补充的内容
- **[主题X]** —— 优先级：高/中/低
  建议加入：[文件] 的 [具体章节/行号附近]，因为 [该处现有框架缺什么 / 该条目与论文的什么形成互补]
- **[主题Y]** —— 优先级：高/中/低
  建议加入：[文件] 的 [具体章节/行号附近]，因为 [...]
  （如果找不到明确的归属位置，写「暂未找到明确的归属位置」）

## 数据集
[如有新数据集，简要描述；如无则写"无新数据集"]

## 总体判断
[一句话：是否有实质性新信息？]
```
