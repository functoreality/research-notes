# 重构审查

重构审查同时检查三件事：目标结构是否合理、来源信息是否守恒、
未来读者是否能找到并理解内容。单一审查视角不能替代其他视角。

## 1. 每批自检

主执行者完成一个实质迁移批次后，先根据来源去向记录逐项检查：

- 每个源信息点是否有目标或留存位置
- 原判断的对象、范围、力度和公式是否保留
- 新父节点是否提供了正确语境
- 源端共享正文是否已移除
- 原框架是否出现子节点错挂或语境断裂
- UID、链接和 Tab 层级是否有效

自检通过后再启动两个全新上下文的只读审查者。

## 2. 未来读者审查

### 角色

审查者是熟悉研究领域、但没有参与本次重构的未来读者。
不先阅读重构任务规范，也不查看预期答案。

给审查者目标文件、必要入口和下列审查要求。审查者不得修改文件，
不得创建其他审查者。

### 问题驱动的渐进查阅

1. 根据目标框架主题推演二至三个未来可能带着回来查的问题
2. 对每个问题先只扫描当前层各行开头
3. 根据行首判断是否读完该行或展开子层
4. 只沿看起来相关的路径查找答案，不无目的通读全文

报告：

- 某行能回答问题，但行首没有显露相关性
- 答案藏在子树中，但父节点没有提示
- 必须逐行通读才能找到答案
- 指代不清、概念首次出现缺少说明或存在多种解读
- 关键信息顺序违反自然理解路径
- 父节点折叠后不是完整表达，或子节点只是续句

报告需给出具体位置、读者当时的问题和困惑原因，不提供泛泛风格评价。

## 3. 任务准则审查

### 输入

审查者完整阅读：

- 本 Skill 和本轮相关 reference
- 本轮来源块及必要祖先语境
- 目标局部及必要祖先语境
- 来源去向记录
- 可用时读取约定基线到当前状态的 Git diff

审查者只报告，不修改文件，不创建其他审查者。

### 内部结构检查

- 分类轴或展开轴是否回答父节点提出的问题
- 每条父子边是否直接，是否缺少桥接层
- 兄弟节点是否处于相近抽象层级
- 一般方法、组件、条件和实例是否错层
- 浅层节点能否覆盖父问题允许的主要对象形态
- 是否存在重复节点、孤立节点、过深层级或过宽分支
- 共享手段回指是否保留各目的下的直接关系
- 占位是否明确表示尚无来源支持，而非暗示问题已经解决

### 外部覆盖检查

- 每个删除或改写的信息点是否有语义对应位置
- 是否出现含义变窄、判断变强、条件丢失或公式变义
- 一般知识是否退回论文专名或特定数据形态
- 原框架留存内容是否仍有完整父链
- UID 是否随实质内容移动，文献 UID 是否重复引用
- 链接角色、作用域、目标粒度和点击提示是否清楚

关键词匹配无法确认的项目列为语义复核项，不直接判为丢失。

## 4. 主执行者处理反馈

审查意见是证据，不是修改命令。主执行者逐条判断：

- 问题是否真实存在
- 是否由本轮重构引入
- 表面问题是否来自更深的结构错误
- 建议修复是否会损失原有抽象、信息量或判断力度
- 是否存在副作用更小的修复方式

修正后重新检查相关来源去向、结构、UID 和 diff。
局部措辞修复通常不重启整轮审查；改变顶层结构、迁移归属，
或大范围改写后，应重新执行两个视角的审查。

## 5. 中期累计审查

在以下时机执行一次新的只读审查：

- 完成一个主要分支
- 连续完成多个迁移批次
- 准备由用户提交 Git commit
- 分批迁移已使整体去向难以仅靠工作记忆追踪

审查步骤：

1. 查看约定基线到当前状态的 Git diff
2. 枚举旧文件中删除或改写的信息点
3. 在新框架和保留后的原框架中寻找语义去向
4. 报告丢失、变窄、错挂、无意重复或语境断裂
5. 列出只能由语义判断确认的项目
6. 检查链接的角色、作用域、位置和目标粒度

若没有可靠 Git 基线，改用完整来源清单和去向记录，不因此跳过累计审查。

## 6. 最终全盘审查

全部迁移和导航收尾完成后，启动一次全新上下文的只读审查。
核查范围包括：

- 所有来源信息均有明确去向，技术含义没有无意丢失
- 新框架没有重复、错挂、孤立节点或不完整父子关系
- 原框架移除共享内容后，整体目的和场景链条仍完整
- 单框架重组后，范围内旧信息均已进入新结构或明确留存
- `((UID))` 可解析到预期定义，新增 UID 唯一
- 链接能区分局部指代、整句证据、具体实例和相关主题
- Tab 层级有效，没有缩进跳跃和空节点
- 从原框架和常见研究问题出发，均能发现新知识位置

最终审查发现问题后，由主执行者修正并对受影响部分重新检查。
最终全盘审查不能由每批局部审查或中期审查替代。

## 7. 审查频率

每个实质迁移批次均执行自检和双审查。中期审查频率根据迁移规模和
认知负担调整，通常在一个主要分支完成或若干批次后执行。

批次大小和审查频率服务于信息可追踪性，不机械使用固定 bullet 数量。
若用户要求逐批确认，在汇报后暂停；用户已经授权连续执行时，
只在出现实质范围、结构或删除边界变化时请求新的决定。
