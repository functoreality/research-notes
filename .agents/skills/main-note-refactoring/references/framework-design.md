# 目标框架设计

## 1. 从来源还原问题

不要从旧标题或已有分类名称直接拼接新目录。先回答：

1. 各来源实际在讨论什么对象或过程？
2. 它们共同要解决或描述的子问题是什么？
3. 哪些维度只属于某一场景，哪些能跨场景比较？
4. 单框架重组时，旧结构为什么不利于理解或查阅？
5. 未来读者会带着哪些问题回来寻找这些内容？

用这些答案确定新框架的组织目的。原计划或旧草案是候选骨架，
不能代替对来源宽度和深度的重新检查。

## 2. 同时服务技术逻辑和查阅路径

目的手段关系是主要的结构判断依据，但最终产物是可折叠查阅的主笔记，
不是完整的分析树。

对每个主要分支同时检查：

- 技术逻辑：父节点提出什么问题，子节点怎样直接回答
- 查阅逻辑：未来读者会从什么行首或父节点判断是否展开
- 扩展逻辑：未来加入同类内容时，是否有稳定位置

如果严格保留每个中间目的只会增加展开次数，而不帮助理解或分类，
可把它压入父节点末尾、行首标签或一行完整表述。
如果省略中间层会让一般方案、组件和实例混在一起，则必须补层。

## 3. 设计节点和父子关系

每个节点表达一个完整、可辨认的信息点。节点可以是待解决的问题、
可复用手段、性质、条件、实例或证据，但它与父节点的关系必须清楚。

逐条检查父子边：

1. 子节点是否直接回答父节点提出的问题？
2. 若它只是远处有帮助，是否缺少更直接的中间问题？
3. 若它只是性质或适用条件，是否被误写成并列方案？
4. 折叠子节点后，父节点是否仍是完整表达？
5. 父节点是否提示了子树会回答什么？

不把纯分类标签、方法名或论文名当作自解释的框架节点。
需要分类节点时，写出该分类帮助读者判断的对象或问题。

## 4. 统一同级展开轴

同一组兄弟节点应回答同一种问题，并处于接近的抽象层级。

常见展开轴包括但不限于：

- 问题由哪些共同必要部分构成
- 有哪些可替代方案
- 一个已选方案由哪些组件实现
- 一个对象有哪些可独立比较的设计维度
- 怎样测量或判断某项性质
- 某一般方法在哪些场景中实例化

不要把一般方法、方法组件、实施条件和具体论文实例直接平铺。
复杂关系同时包含多种展开轴时，补充中间节点将它们分层。

同一父节点下若采用封闭分类，检查分支是否重叠或遗漏。
开放方案空间只需形成有区分度的主要方向，不声称穷尽全部方案。

## 5. 检查覆盖范围和抽象层级

通用框架的浅层节点应覆盖父问题允许的主要对象形态。
坐标、图像、token 或某篇论文的专用输入通常不能与一般设计维度并列。
先寻找能覆盖多种输入的上位问题，再把特定形态作为方案、条件或实例。

若只有一个孤立特例，尚不能形成可复用维度，通常留在原场景。
若它揭示了当前骨架未覆盖的一般问题，先提炼该问题，再判断其他来源是否
支持相同维度。

父节点提出某项设计问题后，子树应给出相应答案。
来源暂时没有具体方案时，可以保留“需另行定义”等明确占位，
不能让父节点暗示该问题已经被现有子项覆盖。

## 6. 区分一般方法和实例

先记录能脱离单篇论文成立的一般操作、判断或公式，
再把论文或算法实例挂在其采用的方法下。

判断一个节点是不是实例时，临时忽略它的链接：

- 正文仍给出可复用操作或判断：它是一般知识，链接只是来源
- 正文主要说明某方法采用了上层策略：它是实例
- 实例还关联另一个主笔记主题：可增加相关链接，
  但不在实例下复述另一框架的完整结构

默认行为若已由一般规则说明，通常不需要再列普通实例。
实例优先用于说明非默认选择、适用边界或反直觉结果。

## 7. 平衡宽度和深度

宽度过大会增加一次扫视的候选数，深度过大会增加展开次数。
是否增加中间层，取决于减少扫视负担的收益是否大于新增展开成本。

可参考以下信号：

- 直接子节点明显超过约十项时，寻找能形成稳定维度的一组内容
- 只有一个子节点且中间层只承担分类作用时，考虑压平
- 一般方案、组件和实例开始混杂时，应加层
- 读者常直接检索的维度可以适当靠近浅层
- 同一手段服务多个目的时，先保留各目的下的直接关系；
  只有集中比较确有价值时，才建立共享子树并在各处回指

“约十项”只是扫视成本的经验信号，不是格式上限。

## 8. 大纲阶段的产物

在正文迁移前，目标大纲通常只包含：

- 顶层问题和主要分支
- 能确定的关键中间层
- 必要的占位说明
- 少量用于验证容纳能力的来源示例

不要为了证明大纲可用而提前搬运大量正文。
用每个来源的代表性内容做反向安放测试：如果某个重要信息点只能按名称
勉强塞入，而无法沿合理父子关系进入框架，说明骨架仍有跳步或边界错误。

用户未批准目标结构时，在此阶段暂停。用户已明确批准完整结构或授权边做边调时，
可继续迁移，但发现顶层组织轴需要改变时仍需说明。

## 9. 结构验收

- 主要来源维度都能自然进入目标框架
- 父子边直接，同级展开轴清楚
- 一般方法、组件、条件和实例没有错层
- 浅层节点足以覆盖目标框架声明的对象范围
- 宽度和深度适合折叠查阅
- 父节点能提示子树内容，每个节点自身表达完整
- 尚未覆盖的问题以明确占位或范围说明呈现
- 没有为形式完整而引入无用层级
