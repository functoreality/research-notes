# 模式与范围

## 1. 识别模式

### 多框架整合

适用于两个或以上既有框架分别讨论同一类子问题，需要将共享知识集中到
独立框架的情况。

目标不是合并旧段落，而是：

- 还原这些来源共同回答的问题
- 提取脱离单一场景后仍成立的知识
- 保留各来源怎样使用该知识实现自身整体目的的场景内容
- 建立可独立查阅和继续扩展的新框架

### 单框架重组

适用于一个既有框架的内容仍有价值，但旧的分类轴、父子关系或查阅路径
需要整体重做的情况。

目标不是增加新知识，而是建立旧信息点到新结构的完整映射。
同一文件内移动仍属于知识归属变更，需要来源去向记录和完整性审查。

### 主动发现候选来源

这是前两种模式的可选扩展，不是独立的迁移授权。
仅在用户明确要求或允许 AI 检索其他相关位点时启用。

AI 可以提出候选，但候选进入正式范围前仍需通过语义检查。
如果纳入某候选会改变目标框架边界，或用户可能基于领域细节作出不同判断，
先展示候选及差异，等待用户决定。

## 2. 定义稳定范围

### 用户明确给出来源

优先使用用户给出的文件、UID 子树、标题子树或其他内容边界。
UID 子树的范围包括沿父子缩进实际归属于该 UID 的内容，
不包括同属更大主题、位置相邻或语义近似的节点。

记录每个来源的：

```text
文件 | 来源根 UID 或标题 | 必要祖先链 | 当前迁移状态
```

行号可辅助打开文件，不作为跨轮次边界。每轮恢复时从稳定边界重新展开，
识别尚未处理的内容。

### 用户只描述主题

先检索可能相关的文件和节点，形成候选清单，不立即迁移。
候选清单至少说明：

- 文件和稳定位置
- 候选内容讨论的对象与功能
- 它与目标主题共享的概念
- 可能不应合并的细微差异
- 建议纳入、排除或请用户判断

## 3. 多框架的归属判断

判断一个信息点能否迁入共享框架时，逐项比较：

1. 讨论对象是否为同一语义类型
2. 输入、输出、定义域和值域是否兼容
3. 它提供的是共享问题的定义、方案、约束或性质，
   还是原场景怎样使用该子要素的专门逻辑
4. 脱离原父节点后，该判断是否仍成立
5. 迁入后能否用目标框架的语言准确表达，而不改变技术含义

共享知识通常包括可跨场景比较的对象、设计维度、方案、约束、训练方式和
下游使用方式。场景特有知识通常包括原框架的整体目的、专门接口、外部约束、
实例中的后续计算，以及离开该场景便失去意义的判断。

不要因为两个量都能“控制网络”或两个方法都使用相似符号，就认定它们属于
同一框架。先检查它们输出的是离散类别、连续条件、物理量还是其他对象。

## 4. 单框架的边界判断

先确定本次重组覆盖整个文件、一个 UID 子树，还是若干明确分支。
范围外的相邻内容不因新结构更美观而获得修改授权。

对范围内每个节点区分：

- 实质知识：定义、判断、方案、条件、公式、实例和证据
- 组织语境：旧父节点提供的分类轴、目的或共同前提
- 导航结构：UID、跨文件入口和相关链接

新结构可以替换组织语境，但不能悄然丢弃实质知识。
旧父节点若同时承载独立判断，应迁入相应位置，不能把它只当目录删除。

## 5. 处理不确定候选

以下情况视为实质歧义：

- 对象或映射类型存在细微但会改变结论的差异
- 迁入需明显扩大目标框架定义
- 只有论文类比或共同术语，没有直接共享的问题
- 用户的领域判断可能推翻 AI 的归属结论
- 迁入需删除仍可能有独立价值的原判断

遇到实质歧义时：

1. 保留原处
2. 说明共同点和关键差异
3. 给出纳入后与不纳入时的结构影响
4. 请求用户决定

如果只是不影响结构的措辞选择，可由执行者按现有笔记风格决定，
不设置额外确认点。

## 6. 范围变化

执行中发现新来源或目标框架需要扩展时，区分：

- 已批准范围的自然细化：可以继续
- 新增独立来源、改变目标定义或扩大删除范围：先确认
- 仅修复本轮移动造成的失效链接或错挂：属于必要收尾
- 顺手改善范围外旧内容：不执行

将确认后的范围变化写入任务记忆或计划文件，避免只依赖对话上下文。

## 7. 跨轮次任务记忆

任务跨越多个会话、模型或上下文压缩时，维护一份独立任务记忆，至少记录：

- 当前模式、目标框架和稳定来源边界
- 已批准的结构、迁移范围和用户确认节奏
- 已完成、待处理、保留和暂缓的来源块
- Git 基线或其他完整性核验依据
- 已发现的语义边界、术语映射和不可合并概念
- 中期与最终审查状态

执行中发现可复用且会影响后续批次的任务专门规则时，记录规则及其动机。
一次性的局部取舍只记去向，不上提为普遍规则。

恢复任务时先重读任务记忆、本 Skill 和当前阶段要求的 reference，
再从稳定来源边界核对文件现状。文件与记忆不一致时，以用户当前文件为准，
更新任务记忆，不把旧内容自动写回。
