# “路由 h”分支重构方案

> 本方案已由 `route-h-refactor-design-v2.md` 替代，保留用于比较设计变化。

## 设计结论

保留当前第一层机制划分：`预设映射`、`显式分类器`、`损失隐式定义`。
这一层回答类别依据怎样获得。三者在产生方式、训练接口和部署条件上差异较大，
放在浅层便于比较，但不要求部署模块彼此互斥。例如损失产生的训练期分配，
可以再蒸馏成显式分类器。
不把 `x` 与 `j` 提升到它们之上，以免同一种机制的可迁移做法被拆散。

`x`、`j`、完整输入 `s` 和已知条件的差别，改为各机制内部的“路由依据”。
只在这种差别真实影响方案组织时展开，不为形式对称制造空分支。

## 共同记号

- 元素级输入为 $s:J\to X$，当前元素可写成 $x=s(j)$。
- `j` 表示角标及其已有结构，例如网格位置、序列次序或图邻接。
- `s` 表示完整输入，允许规则比较多个元素或分析整体几何。
- `c` 表示输入之外已知的时间标签、方程参数、材料区域或界面等条件。
- 预处理可把 `j` 重排为 `j'`，也可把完整输入重构为
  $T(s):J'\to X'$。后一种情况改变了分类单位。
- `x`、`j`、`s`、`c` 是依赖来源，不天然互斥。需要分类安放时，
  按产生类别所需的最小信息归位；确实需要多个独立来源时，注明组合依据。

这些记号用于澄清依赖关系。正式笔记可沿用邻近节点已有的自然语言，
不必在每个例子中重复写公式。

## 拟议框架

- 路由 $h$：选择预设、显式学习或由损失隐式产生的类别分配机制
	- 预设映射：不用训练分类器，按固定规则产生类别
		- 直接赋类：中间计算直接产生最终类别，不先建立供另一规则切分的新表示
			- 依赖签名：按产生类别所需的最小信息组织，多个来源可组合
				- 单元值或坐标 $x$：按数值区间、坐标块或当前表示中的区域直接分类
					- 固定时间区段：保留抽象方案，不再用 STCast 作为纯预设实例
					- INR 固定区域：矩形或其他人工区域划分，落盘时寻找更精确 UID
				- 已有角标 $j$：按原有网格、序列或图结构直接分组
					- 稀疏注意力：`o2cg1y`
					- NO 空间交互范围：`o8h98r`
					- ViT 邻域下采样：`p8jh36`
				- 全集几何或全局语境：分类需要比较多个元素或分析完整域结构
					- SpiderSolver：`_q14g1z`，按边界聚类和到边界距离划分域内点
						- 跨形状对齐：模板分类经 point matching 迁移，作为附加步骤
				- 已知条件 $c$：分类需要输入外部已有的标签、参数、区域或界面
					- INR 已知物理区域：当前 `n2pk9m` 范围过宽，落盘前细化链接
				- 组合依据：两个以上独立来源缺一不可时，说明各自作用
		- 变换后赋类：先用固定预处理构造新的排列或分类单位，再按其结构切分
			- 重排角标 $j\to j'$：保留原元素，只人为建立新的次序
				- MMET：用 Hilbert 曲线排序点集后切成定长 patch
					- 链接：`_p8aj27` 支撑 Hilbert 排序，完整操作落盘前补充精确 UID
					- 采用原因：`_p8aj1s`，避免可学习划分依赖训练条件
			- 重构输入 $s\to T(s)$：转换模态或单位系统，再分类新单位
				- 路由组成：$h=h'\circ T$，$T$ 转换表示，$h'$ 对新单位赋类
				- 文本图像化：`q8ph8x`，渲染为图像后按图像 patch 打包
	- 显式分类器：带参数映射从观测中输出分类结果
		- 设计维度：分别比较观测、参数和先验怎样进入分类器
			- 观测来源：以下来源可以单独使用，也可以组合
				- 单元内容 $x$：读取当前元素的值或特征
				- 当前角标 $j$：读取位置、次序或邻接等已有结构
				- 集合语境 $s$：读取完整输入或由多个元素聚合出的上下文
				- 已知条件 $c$：读取额外标签、方程参数或区域信息
			- 参数关系：说明路由与后续处理器怎样共享或分离表征网络
				- 独立编码
				- 共享编码
			- 先验融合：说明已知信息怎样影响可学习分类结果
				- 输入特征
				- 分数偏置
					- STCast：学习内容分数与月份先验共同决定路由
						- 链接：`_q8mi4t` 只支撑月份先验，落盘前为完整得分式新增 UID
				- 候选限制
		- 场景入口：以用途标签说明可学习路由落在哪类任务中
			- 集合打包，Transolver：`o2cg0f`
			- 集合打包，Opt_RNO：`p8ge27`
			- 区域分流，自适应 FNO：`p8ai7w`
	- 损失隐式定义：比较处理器损失或残差，产生训练期类别
		- 分配依据：用目标值、处理器误差或可计算残差比较类别
		- 运行阶段：区分产生训练分配与部署时复现分配
			- 训练期：比较可用损失并更新路由或处理器
			- 推理期：现场复算分数，或蒸馏显式分类器
		- 观测来源：有材料表明 $x$、$j$ 或 $s$ 会改变分配规则时再展开

## 划分逻辑

`预设映射` 先按计算流程分成“直接赋类”和“变换后赋类”。中间计算若直接
产出最终类别，仍属于直接赋类。只有先产生可独立描述的新排列或新单位系统，
再由另一条规则切分时，才属于变换后赋类。下一层的依赖签名按最小必需信息
回答规则读取什么，避免把“结构先验”和“直接索引”等重叠概念并列。

SpiderSolver 暂放在 `直接赋类—全集几何或全局语境`。边界谱聚类和距离扩展
直接产出它的类别，并没有先得到一个供另一规则分块的通用新角标。几何信息
在具体数据中可能属于 `j` 的结构，也可能属于 $s(j)$ 的坐标，因此不强行绑定
某一种表示。若后续原文表明它先产生独立表示再切分，可移入“变换后赋类”。

空间填充曲线则明确先把无序点集重排为序列，模态转换还会改变元素集合，
因此二者都属于“变换后赋类”，但分别放在重排角标和重构输入下。

`显式分类器` 用“设计维度”统领观测来源、参数关系和先验融合，
再把具体方法放入独立的“场景入口”。前三者是正交维度，不是互斥方案。
观测来源内部也允许组合，因此这里区分 `x`、`j`、`s`、`c`，但不把它们
误写成彼此排斥的分类器类型。

`损失隐式定义` 分开记录分配依据和运行阶段。现有材料不足以证明按 `x`
或 `j` 拆分能改善检索，因此只保留观测来源占位，不制造空的具体分支。

## 多入口安放表

| 内容 | 路由构造位置 | 目的用途位置 |
| --- | --- | --- |
| `o2cg1y` 稀疏注意力 | 预设映射、直接赋类、已有角标 | 分组、限制元素交互 |
| `o8h98r` NO 空间交互 | 预设映射、直接赋类、已有角标 | 分组、限制元素交互 |
| `p8jh36` ViT 下采样 | 预设映射、直接赋类、已有角标 | 打包、按类聚合元素信息 |
| `p8ai7w` 自适应 FNO | 显式分类器、区域分流实例 | 分流、不同单元用不同处理器 |
| `q8ph8x` 文本图像化 | 预设映射、变换后赋类、重构输入 | 若需强调打包用途，再设简短入口 |

同一 UID 出现在两处时，两处分别回答“为什么分类”和“依据什么分类”。
正式落盘时按两个位置的局部问题保留必要说明。通常把完整技术细节放在主要
位置，另一处用带场景标签的短链接引导读者；若两个入口需要不同解释，
可分别保留最低限度的角色说明。
