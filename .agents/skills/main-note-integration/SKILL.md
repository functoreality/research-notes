# 主笔记集成

本 skill 将已经消化的单篇论文内容纳入笔记系统。它既可在 `paper-to-notes`
完成计划和文献笔记草稿后的同一会话中继续执行，也可在新会话中接收已有文件。

## 输入与边界

开始前确认以下输入：

1. 迁移计划：通常为 `论文方法名-arXivID-plan-模型名.md`。
2. 已经审阅并允许正式写入的文献笔记：可以是临时草稿，也可以是已在
   `raw/` 中的正式条目。
3. 笔记根目录及目标主笔记文件。

如果当前会话刚完成 `paper-to-notes` 的 Writing Workflow，前两项已在上下文中，
无需重复索取。若用户明确要求迁移，即视为允许执行本 skill 的文献笔记正式写入和
主笔记写入；`keywd.md` 的新增关键词仍按第四节单独向用户说明并取得同意。

文献笔记为临时草稿时，先吸收已确认的反馈，将它写入正式文献笔记并补齐 UID，
再迁移主笔记。文献笔记已经是正式条目时，不得重复追加，只检查其是否为每条待迁移
断言提供了合适的来源 UID，缺失时才补充。

本 skill 只向既有主笔记框架增补来自一篇论文的内容。发现需要改变旧内容的组织维度
或重排多个既有分支时，说明原因并暂停，交由未来的主笔记重构工作流处理。

> 本文件描述写入笔记系统时的**具体操作方法**（UID 生成、文件选择、插入位置、链接规则等）。
>
> 文献笔记的写作规范（格式、风格、压缩原则等）见
> `../literature-note-writing/SKILL.md`。

## 一、准备工作

### 1.1 生成 UID

笔记中使用 6-7 位 36 进制 UID 作为锚点标识。写入前需先用脚本生成：

```bash
# 脚本位于 outline-read skill 目录（路径相对于本 skill 的 base dir）
../outline-read/scripts/gen-uid --dir raw
```

脚本 stdout 输出一个基础 UID（如 `q6uk3b`），stderr 输出使用提示（如何递增、文献笔记格式等）。

**需要多个 UID 时**：在基础 UID 上逐次递增（36 进制），如 `q6uk3b` → `q6uk3c` → `q6uk3d`。

**UID 前缀约定**：
- **文献笔记 UID**：加下划线 → `{_q6uk3b}`，表示该锚点位于文献笔记中
- **主笔记 UID**：不加下划线 → `{q6uk3b}`

**未来引用语法**：
- 未来在主笔记中引用某 UID 时，行内引用用双小括号包裹 `((UID))`
- 引用文献笔记 UID 保留下划线前缀 `((_q6uk3b))`；引用主笔记 UID 不带前缀 `((q6uk3b))`
- outline-read 解析依据括号内字符串精确匹配，误用下划线前缀会使链接失效

### 1.2 确认目标文件

根据分析报告中的「建议加入」字段，确认需要写入的：
- 文献笔记文件（如 `raw/AISClit9.md`、`raw/freeLit4.md` 等）
- 主笔记文件（如 `raw/PINN.md`、`raw/aisc1.md` 等）
- 如涉及新关键词，还需要推荐更新 `raw/keywd.md`，最终是否采纳由用户决定

## 二、写入文献笔记

本节只在输入是临时草稿，或现有正式条目缺少待迁移内容的来源 UID 时执行。
已经正式写入且来源完备的条目直接进入第三节。

### 2.1 选择文件和追加位置

根据论文主题匹配对应文献笔记系列：
- AI for Science 综合 → `AISClitN.md`（优先用最新一期）
- 神经算子 → `NOlit.md`
- 动力系统 → `dynSysLit.md`
- 降阶模型 → `ROMlit.md`
- Transformer → `TfLit.md` / `TfLit2.md`
- 自由阅读 → `freeLitN.md`（优先用最新一期）

**新条目追加在文件开头**。如果当前文件已经很长（如超过 800 行），可考虑新建下一期（如 `AISClit11.md`）。

### 2.2 标题行格式

> 标题行的写作原则和完整规范见
> `../literature-note-writing/SKILL.md` 第 3 节。
> 此处仅列出格式要点和示例。

格式：`* 方法名-arXivID 一句话描述`

- **方法名**：论文提出的核心方法或模型的简称。没有显著方法名的可省略
- **arXiv ID**：取标识符后段（如 `2604.23098`），不要前缀 `arXiv:`
- **连字符**：两者都有时用 `-` 连接；只有其一不写连字符；都没有时直接从内容概括开始

示例：
```
* ICM-2604.23098 ICON 上下文式预测本构关系，条件为平衡方程系数
* 2308.02287 分类模型输出引入冗余类可提效果
* AlphaFold 架构创新关键，不全靠堆算力
```

### 2.3 正文结构

> 正文的写作原则（压缩、归因、评注、引文等）见
> `../literature-note-writing/SKILL.md`。
> 此处仅列出文件骨架模板和项目特定约定。

```markdown
* 方法名-arXivID 一句话描述
	* "Paper Title in Full", （如果有）发表位置简写
		* Author1; Author2; Author3;
		> created on YYYY-MM-DD by [软件框架 + 模型名]
	* 摘要摘录
		> 摘要中值得注意的原句（中文翻译）……
	* （章节名/要点概括）
		> 原文引用（中文翻译）……
		* 评注或展开……
```

- 作者列表：分号分隔
- 发表位置简写：若仅有 arXiv 预印本，省略逗号和发表位置

**`created on` 行的规则**：
- **AI 生成的笔记**：日期后补充软件框架和模型名，如 `> created on YYYY-MM-DD by OpenCode + deepseek-v4-pro`
- **人类创建的笔记**：只有日期。**不要改动已有的人工笔记**

**原文引用**用 `> ` 格式；自己的评注不加 `>`。

### 2.4 分配 UID

在文献笔记中，为每个**可能被主笔记引用**的内容行分配 UID。UID 放在行尾，紧跟着标点符号（如分号）：

```markdown
	* 上下文条件：eqn(6) 每节点 n 提供一个 token；{_q6rk6g}
	* 无监督训练：残差作为 loss；{_q6rk5h}
```

不是每行都需要 UID，只为那些在分析报告中被认为有迁移价值、将要在主笔记中引用的内容行分配 UID。

#### 2.4.1 为主笔记准备可溯源锚点

主笔记中的实质判断需要能沿 UID 回到原论文。为某条待迁移内容分配 UID 时，优先选择：

1. 原文摘录或其忠实翻译
2. 带明确章节、图或公式出处的忠实压缩
3. 若原论文确有相应内容、但文献笔记尚未记录，先补写或微调文献笔记，创造上述位点

`（AI 评）`（包括它可能带有的子节点）也可有 UID，但一般不作为主笔记的首选来源。
只有无法用原论文的内容支撑、且这条判断本来就是笔记者的研究设想或综合结论时，才考虑引用它；
主笔记中应相应标出“评”“待验证”等性质，并能说明为什么不改用原文位点。

同一篇论文若支撑多个独立判断，应在文献笔记中为各判断准备不同 UID，
而不是让主笔记的多个判断共用一个宽泛的来源。

### 2.5 文献笔记的链接规则

- **文献笔记内不应包含 `((UID))` 交叉引用**（除非有极特殊的理由）。
- 所有交叉引用都在主笔记中进行。
- 每个文献笔记的 UID（如 `{_q6rk6g}`）在主笔记中应**仅被引用一次**。

这条规则的理由：文献笔记存在于特定论文的语境中，该语境反映作者原意，不宜轻易改动（是「死」的）。主笔记的语境则是「活」的，会随着笔记增长而不断延伸。将链接集中在主笔记中，可以保持文献笔记的稳定性和主笔记的灵活性。

## 三、写入主笔记

### 3.1 写入前审视

分析报告给出的位点建议是逐个要素独立判断的初步结果；多个要素的位点可能存在耦合（共享同一父概念、同一论文的不同案例、互补视角），独立分析容易低估这些关系。
实际写入前，增加一步审视：

**3.1.1 快速扫描**：过一遍本次要迁移的所有点，只做轻量标记——
哪些点共享父概念？哪些是同一主题的不同侧面？
不提前设计结构，仅在工作记忆中标记。

**3.1.2 内部来源映射**：在工作记忆或临时草稿中，为每条待迁移的实质内容确认：

```
主笔记断言 | 文献笔记原文位点 | 文献 UID | 证据类型
相关性只筛候选 | “约 10% 特征过阈” | {_...} | 实验结论
```

这一步不必写入正式笔记，也无需主动展示给用户。
若无法填出原文位点，先按 §2.4.1 补全文献笔记；仍无法建立对应时，再向用户说明是否保留评注型内容。

**3.1.3 逐个写入时的检查**：每写一个点之前，检查它是否与 **已写入的点**有耦合。如果无耦合，直接按 §3.2-§3.7 流程写入；如果有耦合，按以下策略决策：

- 两点共享父概念，应将它们归入一个新建的子框架节点下。
	如果新建节点意味着改动已写入的内容（包括 UID 分配、交叉引用），暂停并说明情况，由用户决定是重构还是接受现状。
- 两点共享父概念，但彼此有重要区分，不应平铺并列。
	在共享的父节点下引入一个区分轴（如「是否跨物理 regime」「基于微调还是零样本」），
	使两点按此轴并列，同时保留共享的父概念。
	是否需要区分轴可在分析报告基础上即时判断，不必等到 `现有框架调整建议` 中已有预判才做。

**3.1.4 事后复核**（可选）：本次所有点写入完成后，回看它们作为整体是否揭示了之前未识别的结构。
如有，记录下来供后续参考，不要求在本次 session 中调整。

### 3.2 找到直接引用位置

根据分析报告中「建议加入：」下第一个「[文件] 的 [具体章节/UID 附近]」定位。

```bash
# 1. 先用 outline-read 看目录结构
../outline-read/scripts/outline-read --dir raw PINN

# 2. 有 UID 参考点时，直接跳转
../outline-read/scripts/outline-read --dir raw --uid n3bg3i

# 3. 用 read 看周围原文，理解上下文和层级
read raw/PINN.md <start_line> <range>
```

在定位之后，确认该位置的**组织目的**是否与新内容的概念范畴匹配：
不要仅凭节标题中的关键词判断匹配（如「评估」标题下的节可能侧重架构层面的评估方法论，而非功能层面的迁移能力评估）。
如果组织目的不匹配，另找匹配的节或参照 §3.1 考虑新建框架节点。

**关键**：在插入前，必须充分阅读目标位置周围的原文，理解当前的层级结构、讨论脉络。
新内容应自然延伸已有讨论的语境，而非突兀插入。
如果发现新内容与该位置讨论话题存在隐含差异、并非完全匹配，考虑重找主笔记插入位点。

**在确定挂入层级前，先追溯完整概念链**：

1. 确定目标父节点后，拆出该要素到父节点的完整概念链（常见形式是目的手段链），逐层展开所有中间概念。
2. 逐一检查链条中各层在笔记中是否已有对应子框架——已有的直接挂入；未展开的判断该层是否有多个并列条目：有则新建缩进层级，仅有一条则可压缩进同一行。
3. 根据上一步确定最终挂入位置和表达方式。

这不涉及修改已有笔记——仅指调整写入计划中的挂入位置。

例：物理诊断选 checkpoint，目标父节点为 OoD 迁移适配。
目的手段链为「OoD 迁移 ← 适配方式 ← 微调 ← early-stop ← 选 checkpoint ← 物理诊断」。
适配方式、微调在笔记中已有对应层级；early-stop 和选 checkpoint 未展开，且该层无其他并列条目。
最终决定新内容挂在「微调」下（而非作为「OoD 迁移」直接子节点，与「适配方式」并列）。
early-stop 与选 checkpoint 压缩在同一行，作为新加入主笔记内容行的开头 `* early-stop—选 checkpoint—基于物理诊断…`。

### 3.3 跨语境翻译

将文献笔记中有价值的内容写入主笔记时，不应直接复制原文，也不应罗列分类标签。而应进行「跨语境翻译」：

- 文献笔记的内容存在于原论文的语境中（作者的问题意识、实验设定、论证逻辑）
- 主笔记的内容存在于目的手段链条的框架中（这个手段解决了什么子问题、属于哪个方案大类）
- 目标位置本身的框架有自己的组织目的（如「评估」「机制分类」「案例整理」），新内容应服务于该目的
	- 具体做法：先判断目标框架的组织目的是什么，再写本案例在该目的下提供了什么贡献（评估了什么维度/揭示了什么机制/填补了什么空缺）
- 避免用"与框架内已有同级条目的比较"作组织基础
	- 框架内容未来会不断增长，当前预设的比较对象未来可能大幅改变
	- 对比关系作为内容（如反例）时可写，但应服务于框架目的，而非作为标签
- 写入时应以主笔记的框架语言重新表述，使内容有机地融入该处的讨论
- 保留来源能够支持的判断力度和不确定性，不把“可能”“可以”与“已经”互换
- 若保留公式或符号，先比较源、目标对象的含义、定义域、值域及离散或连续性质，
  再统一改写文字和记号；不存在语义对应时，不机械换字母

### 3.4 层级结构

主笔记采用 tab 缩进的大纲结构。插入新内容时：

- **新增顶层分支**：如果是一个全新的子问题讨论，从顶层（无缩进）开始新的一行 `* 主题`
- **在现有分支下扩展**：新行缩进层级 = 被扩展行的缩进层级 + 1
- **同级方案并列**：同一子问题下的不同方案保持相同缩进层级（OR 关系）

逐条检查父子边和同级关系：

- 子节点应直接回答父节点提出的问题，或在父节点明确的展开轴下给出同级方案
- 一般方法、方法组件、实施条件和具体实例不要平铺为同级方案
- 先写可复用的一般操作或判断，再把论文或算法实例挂在其采用的方法下；
  节点是否为实例取决于正文角色，不取决于它是否带文献 UID
- 通用框架的浅层节点应覆盖父节点允许的主要对象形态；
  某个具体输入或论文特例尚不能形成可复用维度时，不把它提升为浅层节点

不要改动已有内容的层级结构，除非分析报告中明确提出了框架重构建议且用户同意。

### 3.5 引用文献笔记 UID

在写入的文本中引用文献笔记的具体内容行：

```markdown
* 上下文方案 ((_q6rk3a))ICM：改写为条件输入映射 (目标系统,s) ↦ r
```

`((_q6rk3a))` 引用文献笔记中的内容（下划线前缀表示文献笔记 UID）

**一引用一 UID 原则**：每个文献笔记的 UID 在主笔记中仅被引用一次。

#### 多条内容共享可扩展分类节点情形

上例适合只迁移一条内容。若新增一个会继续容纳多篇文献的分类节点，建议将引用放在各个实质判断旁边：

```markdown
* 用于机制解释
	* 分离混合激活：((_lit_sae))用 SAE 等稀疏分解，再逐特征检验
	* 相关性只筛候选((_lit_corr))，不能据此直接命名物理机制
	* 检验跨条件稳定性：((_lit_stable))改变参数、时间后，候选特征的空间模式是否仍一致
```

这里“用于机制解释”只说明子项服务的共同目的，是可扩展分类节点，日后可接入其他论文的内容。
它通常不承载某一篇论文的来源，以免让读者误以为其后全部子项都由同一篇论文支持；事实上，即使它本身带有引用，子项也默认不继承该来源。
分类节点若同时包含独立的实质判断，仍可按该判断单独标注来源。

#### 链接角色与放置

放置链接前先判断它是在：

- 补足句子成分，直接引入当前表达所引用的对象
- 标注某个词或短语，说明该局部概念的位置
- 支撑冒号后的整句判断，指出证据或出处
- 为抽象方法提供具体文献实例
- 指向相关主题，提示同一内容在另一场景下的专门框架

链接应贴近它的实际作用域，并用位置、空格和说明文字消除歧义：

- 只标注某个词时，链接与该词相邻，并与不属于指代范围的文字留空格，
  如 `((UID))ensemble` 或 `bagging((UID)) 区别`
- 支撑冒号后整句判断时，优先紧接冒号放置链接，再写具体内容；
  当前句式不适合前置时才放在句末
- 文献链接只提供实例时，明确写成 `例—方法名` 或“例如”，
  不把它放在一般判断末尾，伪装成该判断的唯一来源
- 相关主题链接应写明共同目的、共同手段或比较轴，不只写“相关”或方法名
- 不连续堆放角色不同的链接；需要分别解释时拆成不同节点
- 父子节点都可作为候选目标时，通常保留最能提供所需上下文的一个，
  不机械追求最细粒度

说明文字应让读者不点开链接，也能判断它指向什么、为何值得查看。

### 3.6 追加其他引用位置

当一个技术手段服务于多个不同目的时（即同一文献笔记内容需要在主笔记的多个位置出现），不允许重复引用同一主笔记的 UID。
正确做法：例如，假设手段 X 同时服务于目的 A 和目的 B。

1. （3.2 已完成）在目的 A 的框架下，记录 X₁（手段 X 服务于目的 A 的具体方式），引用文献笔记 UID。
2. 为 X₁ 补充自己的主笔记 UID `{UID_X1}`（无下划线）。
3. 在 X₁ 的下层，注明该手段也服务于目的 B，引用目的 B 的框架位置（如 B 之前无 UID，可自行补充）：
	```markdown
	* 目的 A
		* 手段 X：…具体描述…((_litUID))；{UID_X1}
			* 该手段也可用于 ((UID_B))目的 B
	```
4. 在目的 B 的框架下，记录 X₂，内容可以很简短，直接链接到 X₁：
	```markdown
	* 目的 B；{UID_B}
		* 手段 X((UID_X1))
	```

**核心原则**：
- 主笔记 UID 可以被多次引用（与文献笔记 UID 不同）
- X₁ 是「主版本」，X₂ 是引用它的「次要记录」
- 主版本向次要记录的链接指向其所在框架位置（如 B），而非指向次要记录本身（如 X₂）

### 3.7 （仅需要时）分配自身 UID

主笔记中如果有内容行需要被其他位置引用，而之前未分配 UID，同样现场分配：

```markdown
* 上下文方案 ((_q6rk3a))ICM：改写为条件输入映射 (目标系统,s) ↦ r；{q6rk68}
```

这行内容可以通过 `((q6rk68))` 被主笔记的其他位置引用。

行尾定义 `{UID}` 前通常加中文分号。若前面已有句号、分号或右括号等标点，
不重复添加；不要让 `{UID}` 只隔一个空格直接跟在无标点正文后。

## 四、更新 keywd.md

如果新增的主笔记内容引入了新的关键概念，之前无相关记录，应考虑在 `raw/keywd.md` 中添加关键词条目。
向用户解释计划添加的关键词，获得同意后写入：

```
关键词 keyword：((UID))
```

- 关键词通常同时给出中英文
- UID 指向主笔记中最能代表该概念的那一行
- 若文件中已有类似概念，可追加到其附近，没有则放文件末尾即可

`keywd.md` 是扁平文件（无缩进），不需要用 outline-read 浏览，直接 `read` 或 `grep` 即可。

## 五、约束与注意事项

### 必须遵守

1. **不要改动已有的人工笔记**（包括日期格式、UID、措辞等），除非分析报告中明确建议且用户同意
2. **文献笔记中不放 `((UID))` 链接**（除极特殊情况）
3. **每个文献笔记 UID 在主笔记中仅引用一次**
4. **主笔记 UID 可多次引用**
5. **文献笔记 UID 用 `{_XXX}` 格式，主笔记 UID 用 `{XXX}` 格式**
6. **匹配现有的缩进风格**：用 tab 缩进，保持与周围内容一致的层级深度

### 建议遵循

- 写入前，主动检索笔记中是否已有相关讨论，避免重复或碎片化的记录
- 新内容尽量归入「系统分析层」的成熟框架（如 PINN.md 的 PDE 残差条目、aisc1.md 的本构关系学习条目），而非「方案设想层」的松散框架
- 不确定插入位置时，先保守（暂不写入），向用户说明情况
- 新增的实质内容行尽量各有紧贴的文献 UID，不依赖父节点的引用
- 若 UID 锚到 `（AI 评）`，确认原论文中没有更合适的位点
- 一行若含多个可分别验证的判断，考虑拆分成多行，或为各判断分别标注来源
- 写入后，用 outline-read 或等效方式确认新增 UID 能解析到预期文献笔记位置

### 主笔记写作原则

**检索入口**：行首优先提示读者带着什么问题时值得继续读。
同一节并列不同性质的内容时，可用 `指标—`、`实验—` 等简短角色标签；
比较同一维度的不同取值时，可用 `维度—属性值：具体解释`。
父节点已经给出维度时省略重复部分，只有确实改善定位和比较时才添加标签。

**节点完整性**：一个 bullet 表达完整判断。子节点补充从属信息，
不承担父节点的续句或视觉断行。

**信息层级**：主笔记保留方向性判断和框架概念，具体数据和来源通过 UID 可达。

| 留在文献笔记 | 写入主笔记 |
|------------|----------|
| 具体数字、统计值 | 方向性判断（"不总有益""几乎无关"） |
| 特定模型的具体表现 | 跨模型的可迁移模式 |
| 方法的实现细节 | 该差异引出的概念维度 |
| 数据集的分辨率、样本数、下载链接等细节（除非重要） | 数据类型与特性描述 |

**不写**：
- 元叙述（"这节的动机是…"）——改节标题本身
- 名称标签（`ShiftDamage：…`）——名字在文献笔记，直接写定义
- 冗余总结（"这表明…"）——事实 + UID 已足够

**拆分**：一个 bullet 包含两个独立判断时，拆成两行。
