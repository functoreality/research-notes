# 写入工作流

> **何时阅读**：输出分析报告后，AI 应阅读本文件，再按其中步骤执行。

---

## 步骤一：起草文献笔记并更新迁移计划（自动执行段）

### 1.1 起草并复核文献笔记

- 加载 `../literature-note-writing/SKILL.md`（`literature-note-writing` skill），
  根据论文起草一篇文献笔记
- **将分析阶段得出的目的手段链转化为笔记的组织骨架**：
	- 顶层目的是什么？拆为哪些子问题？每个子问题对应什么手段？
- 计划中认为值得迁移到主笔记里的内容，在文献笔记里均应有相应记录（写完后检查）
- 作为草稿，写入仓库根目录下的
  `paper-to-notes-drafts/论文方法名-arXivID-lit-你的模型名称.md`，
  与 plan 文件放在同一目录，不要直接写入笔记系统的正式文件
	- 文件名中“论文方法名-arXivID”写法同 `literature-note-writing`
	  对文件首行的要求；若发现先前 plan 文件命名错误，请重命名
- 要求遵循 `literature-note-writing` skill 中的写作规范
- 无需包含具体的 `{_UID}` 标记（在步骤二正式写入时分配）
- 文献笔记内不应包含 `((UID))` 交叉引用（除非有极特殊的理由，所有交叉引用仅限于主笔记）

完成 literature-note-writing skill 的复核三步（定性、脚本、子 agent 审视）后，
继续执行 1.2，不在此处暂停。

### 1.2 更新 plan 并起草主笔记条目

- 起草前加载 `../main-note-integration/SKILL.md`，按其中适用的要求设计条目，
  包括来源锚点选择、位点与完整概念链、跨语境翻译、层级关系、主次版本及写作原则。
  此处只设计草案，不执行正式写入、UID 分配或 `keywd.md` 更新。
  具体 UID 标记和链接留到正式整合时处理，草案用行号标注来源。
- 根据写作和复核中获得的新认识，重新审视同目录下已有的 plan 文件。
  若原先的判断、信息点、优先级或建议位点有遗漏或不准确，直接修订。
  若无此类变化，只补齐下面的拟写条目与来源引用。
- 在每个信息点的每个「建议加入」文件及行号下面，起草该位点实际拟加入的
  主笔记 bullet point，遵守 main-note-integration 的信息原子化要求。
  多个独立信息点拆成多行并分别选位点，不为缩成一条而捆绑技术决策。
  将拟写放回目标父节点与相邻条目中试读，按该 skill 的跨语境翻译要求
  匹配局部表述和编排形式，不把文献笔记对应行再摘录一遍。
  同一信息点有多个位点时，分别按各自语境起草。
- 在位点下直接写 `- （拟写）准备加入的内容。〔42〕`，
  不另设“拟写”父节点或代码块。只按拟加入内容的实际从属关系增加子条目。
  plan 开头无需补写配套文献草稿文件名或解释行号约定。
- 每个来源引用只定位文献草稿中的一个具体内容行，如 `〔42〕`，
  不写行号范围或多个数字，括号内不加说明文字。
  按 main-note-integration 中有关来源锚点的要求，选择能够支撑判断的具体内容行。
  若缺少合适锚点，考虑调整拟写条目，或依据原论文补写、微调文献草稿，
  避免从一段范围中随意选取一行，除非这样的调整会明显降低文献笔记本身的可读性。
  多个独立判断按该 skill 的规则拆分并各自标注来源。
- 所有文献草稿修改完成后，再读取带行号的版本（如 `nl -ba`）填写引用，
  检查它们确实支持拟写内容。后续若修改文献草稿，同步刷新 plan 的来源行号。
  同时复核目标主笔记的当前位点，仍遵守不超过 5 行的定位范围及附近 UID 的要求。

示例（行号仅为格式示意，实际执行时须读取文件）：

```markdown
**建议加入**：

- `ML.md` L120-L123，紧邻 `{abc123}`，因为该处缺少基于领域诊断的选择依据
  - （拟写）根据领域诊断指标选择 checkpoint，以识别任务误差未能反映的物理失真。〔42〕
```

以上拟写内容只写入 plan，不写入正式主笔记，不分配正式 UID。
来源行号用于审阅草稿，正式迁移时仍须按 main-note-integration 重新适配内容，
核对锚点并建立 UID 引用。

### 1.3 审视主笔记拟写条目

plan 更新完成后，仿照 `../literature-note-writing/SKILL.md` §5.3 的双视角审视
及反馈辨析原则，并行启动两个全新上下文、无需编辑权限的子 agent。
本轮只审每条拟写及其迁移安排，将其放回实际主笔记上下文判断，不重审整份报告或文献笔记。
两者均需读取当前 plan、配套文献草稿和目标主笔记，实际查看各位点的父节点及相邻条目。
提供所需文件的完整路径，不传递主 agent 的既有评审结论。

- **专家评审**：阅读 `../main-note-integration/SKILL.md` 中适用于拟写的规则，
  只用于评审，不执行整合工作流。检查维度包括但不限于：

  - 位点的组织目的、概念类型与抽象层次，父子及同级关系，主次版本安排
  - 信息原子性、判断完整性，局部句式、术语、符号及压缩程度，是否重复已有内容
  - 来源行与断言是否准确对应、直接支撑，事实与评注是否区分，适用条件及判断力度是否保真
  - 当前文件行号与 UID 定位是否准确，拆分后的各点是否仍有迁移价值

  评审者须结合具体条目自行补充检查角度，指出问题及依据，不以此列表为限。
  需要核实技术事实时可查原论文，判断迁移价值时可查本 Skill 的筛选标准。

- **读者盲审**：只提供上述材料路径和位点定位信息，让它以未来读者身份，
  判断拟写加入实际笔记后是否合适，提出任何不自然之处、疑问或需再确认的问题。
  不提供 Skill、评审指南、专家检查维度或已有反馈。

主 agent 等两者返回后逐条辨析：问题是否成立，是否另有深层原因，建议解法是否恰当、
是否有副作用或更好的改法。只采纳有依据的修改，更新 plan，避免机械服从评审意见。
若需改文献草稿，仍遵守其复核要求，并同步刷新全部来源行号。

若仅有少量局部微调，复核受影响条目后结束；若改动较多，或改变位点、核心判断、
来源对应或层级关系，则再启动一对全新上下文的子 agent 审视更新版本。
此处最多三轮（初次加两次重审），不沿用文献笔记的四轮上限。
第三轮后仍需大改或存在未解决疑点时，交付时说明。
没有拟写条目时跳过本步。

### 1.4 首次请求审阅

文献草稿复核、plan 更新及拟写审视均完成后，**首次暂停并请求用户审阅**。
提供两个文件的链接，解释文献笔记整体逻辑结构及 plan 中的拟写条目，
等待用户确认或提出修改意见。用户可能要求修改后再审阅。

注：1.1 至 1.3 均为自动执行段，不需要请求用户同意，首次暂停点在 1.4。

## 步骤二：改写并写入正式文献笔记

1. 如果用户要求正式写入，结合用户反馈建议，对草稿进行评审和改写
2. 将最终版本**追加**到对应的正式文献笔记文件（如 `raw/AISClitN.md`）的开头（不是结尾）
3. 运行 `../literature-note-writing/scripts/check-note.sh "$FILE"` 验证格式
4. 写入后再次暂停并请求用户审阅

如果用户要求直接写入主笔记，则跳过步骤二、直接进入步骤三，后续追加 UID 也直接在临时文件中进行。

## 步骤三：写入主笔记

用户确认文献笔记后，将分析报告中有迁移价值的内容写入主笔记。

> 此步加载 `../main-note-integration/SKILL.md`（`main-note-integration` skill）。
> 它处理主笔记插入位置定位、跨语境翻译、层级结构规则、主笔记 UID 分配、
> `keywd.md` 更新等。若文献笔记已在步骤二正式写入，它只检查和补充必要的 UID，
> 不会重复追加该条目。
