# 写入工作流

> **何时阅读**：输出分析报告后，AI 应阅读本文件，再按其中步骤执行。

---

## 步骤一：起草文献笔记并更新迁移计划（自动执行段）

### 1.1 起草并复核文献笔记

- 加载 `../literature-note-writing/SKILL.md`（`literature-note-writing` skill），
  根据论文起草一篇文献笔记
- **将分析阶段得出的目的手段链转化为笔记的组织骨架**：
	- 顶层目的是什么？拆为哪些子问题？每个子问题对应什么手段？
- 计划中认为值得迁移到主笔记里的内容，在文献笔记里均应有相应记录（写完后检查）
- 作为草稿，写入仓库根目录下的
  `paper-to-notes-drafts/论文方法名-arXivID-lit-你的模型名称.md`，
  与 plan 文件放在同一目录，不要直接写入笔记系统的正式文件
	- 文件名中“论文方法名-arXivID”写法同 `literature-note-writing`
	  对文件首行的要求；若发现先前 plan 文件命名错误，请重命名
- 要求遵循 `literature-note-writing` skill 中的写作规范
- 无需包含具体的 `{_UID}` 标记（在步骤二正式写入时分配）
- 文献笔记内不应包含 `((UID))` 交叉引用（除非有极特殊的理由，所有交叉引用仅限于主笔记）

完成 literature-note-writing skill 的复核三步（定性、脚本、子 agent 审视）后，
继续执行 1.2，不在此处暂停。

### 1.2 更新 plan 并起草主笔记条目

- 根据写作和复核中获得的新认识，重新审视同目录下已有的 plan 文件。
  若原先的判断、信息点、优先级或建议位点有遗漏或不准确，直接修订。
  若无此类变化，只补齐下面的拟写条目与来源引用。
- 在每个信息点的每个「建议加入」文件及行号下面，起草该位点实际拟加入的
  主笔记 bullet point。通常一条即可，确有必要时用少量子条目。
  表述应适合目标框架的语境和层级，不把文献笔记对应行再摘录一遍。
  同一信息点有多个位点时，分别按各自语境起草。
- 每条拟写内容末尾用 `〔42〕` 或 `〔42-46〕` 引用文献草稿的实际行号。
  不连续来源可写成 `〔42-46, 58〕`。括号内只放数字和范围符号，
  不加“对应文献笔记”等说明，不使用 `((...))`，以免与 UID 引用混淆。
- 在 plan 开头注明一次文献草稿文件名（可用同目录相对链接）及行号约定：
  `拟写条目末尾的〔数字〕为该文献草稿的行号。`
- 所有文献草稿修改完成后，再读取带行号的版本（如 `nl -ba`）填写引用，
  检查它们确实支持拟写内容。后续若修改文献草稿，同步刷新 plan 的来源行号。
  同时复核目标主笔记的当前位点，仍遵守不超过 5 行的定位范围及附近 UID 的要求。

示例（行号仅为格式示意，实际执行时须读取文件）：

````markdown
文献草稿：[Method-2601.12345-lit-model.md](Method-2601.12345-lit-model.md)
拟写条目末尾的〔数字〕为该文献草稿的行号。

**建议加入**：

- `ML.md` L120-L123，紧邻 `{abc123}`，因为该处缺少基于领域诊断的选择依据
  - 拟写：
    ```markdown
    - 根据领域诊断指标选择 checkpoint，以识别任务误差未能反映的物理失真。〔42-46〕
    ```
````

以上拟写内容只写入 plan，不写入正式主笔记，不分配正式 UID。
来源行号用于审阅草稿，正式迁移时再按 main-note-integration 转成 UID 引用。

### 1.3 首次请求审阅

文献草稿复核和 plan 更新均完成后，**首次暂停并请求用户审阅**。
提供两个文件的链接，解释文献笔记整体逻辑结构及 plan 中的拟写条目，
等待用户确认或提出修改意见。用户可能要求修改后再审阅。

注：1.1 和 1.2 均为自动执行段，不需要请求用户同意，首次暂停点在 1.3。

## 步骤二：改写并写入正式文献笔记

1. 如果用户要求正式写入，结合用户反馈建议，对草稿进行评审和改写
2. 将最终版本**追加**到对应的正式文献笔记文件（如 `raw/AISClitN.md`）的开头（不是结尾）
3. 运行 `../literature-note-writing/scripts/check-note.sh "$FILE"` 验证格式
4. 写入后再次暂停并请求用户审阅

如果用户要求直接写入主笔记，则跳过步骤二、直接进入步骤三，后续追加 UID 也直接在临时文件中进行。

## 步骤三：写入主笔记

用户确认文献笔记后，将分析报告中有迁移价值的内容写入主笔记。

> 此步加载 `../main-note-integration/SKILL.md`（`main-note-integration` skill）。
> 它处理主笔记插入位置定位、跨语境翻译、层级结构规则、主笔记 UID 分配、
> `keywd.md` 更新等。若文献笔记已在步骤二正式写入，它只检查和补充必要的 UID，
> 不会重复追加该条目。
