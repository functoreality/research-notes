# 笔记写入操作指南

> 本文件描述写入笔记系统时的**具体操作方法**（UID 生成、文件选择、插入位置、链接规则等）。
>
> **何时阅读**：执行 `paper-to-notes` skill 的「步骤四：写入主笔记」时参考。文献笔记的写作规范（格式、风格、压缩原则等）见 `../note-writing/SKILL.md`。

## 一、准备工作

### 1.1 生成 UID

笔记中使用 6-7 位 36 进制 UID 作为锚点标识。写入前需先用脚本生成：

```bash
# 脚本位于 outline-read skill 目录（路径相对于本 skill 的 base dir）
../outline-read/scripts/gen-uid --dir raw
```

脚本 stdout 输出一个基础 UID（如 `q6uk3b`），stderr 输出使用提示（如何递增、文献笔记格式等）。

**需要多个 UID 时**：在基础 UID 上逐次递增（36 进制），如 `q6uk3b` → `q6uk3c` → `q6uk3d`。

**UID 前缀约定**：
- **文献笔记 UID**：加下划线 → `{_q6uk3b}`，表示该锚点位于文献笔记中
- **主笔记 UID**：不加下划线 → `{q6uk3b}`

### 1.2 确认目标文件

根据分析报告中的「建议加入」字段，确认需要写入的：
- 文献笔记文件（如 `raw/AISClit9.md`、`raw/freeLit4.md` 等）
- 主笔记文件（如 `raw/PINN.md`、`raw/aisc1.md` 等）
- 如涉及新关键词，还需要更新 `raw/keywd.md`

## 二、写入文献笔记

### 2.1 选择文件和追加位置

根据论文主题匹配对应文献笔记系列：
- AI for Science 综合 → `AISClitN.md`（优先用最新一期）
- 神经算子 → `NOlit.md`
- 动力系统 → `dynSysLit.md`
- 降阶模型 → `ROMlit.md`
- Transformer → `TfLit.md` / `TfLit2.md`
- 自由阅读 → `freeLitN.md`（优先用最新一期）

**新条目追加在文件开头**。如果当前文件已经很长（如超过约 800 行），可考虑新建下一期（如 `AISClit10.md`）。

### 2.2 标题行格式

> 标题行的写作原则和完整规范见 `../note-writing/SKILL.md` 第 3 节。
> 此处仅列出格式要点和示例。

格式：`* 方法名-arXivID 一句话描述`

- **方法名**：论文提出的核心方法或模型的简称。没有显著方法名的可省略
- **arXiv ID**：取标识符后段（如 `2604.23098`），不要前缀 `arXiv:`
- **连字符**：两者都有时用 `-` 连接；只有其一不写连字符；都没有时直接从内容概括开始

示例：
```
* ICM-2604.23098 ICON 上下文式预测本构关系，条件为平衡方程系数
* 2308.02287 分类模型输出引入冗余类可提效果
* AlphaFold 架构创新关键，不全靠堆算力
```

### 2.3 正文结构

> 正文的写作原则（压缩、归因、评注、引文等）见 `../note-writing/SKILL.md`。
> 此处仅列出文件骨架模板和项目特定约定。

```markdown
* 方法名-arXivID 一句话描述
	* "Paper Title in Full", （如果有）发表位置简写
		* Author1; Author2; Author3;
		> created on YYYY-MM-DD by [软件框架 + 模型名]
	* 摘要摘录
		> 摘要中值得注意的原句（中文翻译）……
	* （章节名/要点概括）
		> 原文引用（中文翻译）……
		* 评注或展开……
```

- 作者列表：分号分隔
- 发表位置简写：若仅有 arXiv 预印本，省略逗号和发表位置

**`created on` 行的规则**：
- **AI 生成的笔记**：日期后补充软件框架和模型名，如 `> created on YYYY-MM-DD by OpenCode + deepseek-v4-pro`
- **人类创建的笔记**：只有日期。**不要改动已有的人工笔记**

**原文引用**用 `> ` 格式；自己的评注不加 `>`。

### 2.4 分配 UID

在文献笔记中，为每个**可能被主笔记引用**的内容行分配 UID。UID 放在行尾，紧跟着标点符号（如分号）：

```markdown
	* 上下文条件：eqn(6) 每节点 n 提供一个 token；{_q6rk6g}
	* 无监督训练：残差作为 loss；{_q6rk5h}
```

不是每行都需要 UID，只为那些在分析报告中被认为有迁移价值、将要在主笔记中引用的内容行分配 UID。

### 2.5 文献笔记的链接规则

- **文献笔记内不应包含 `((UID))` 交叉引用**（除非有极特殊的理由）。
- 所有交叉引用都在主笔记中进行。
- 每个文献笔记的 UID（如 `{_q6rk6g}`）在主笔记中应**仅被引用一次**。

这条规则的理由：文献笔记存在于特定论文的语境中，该语境反映作者原意，不宜轻易改动（是「死」的）。主笔记的语境则是「活」的，会随着笔记增长而不断延伸。将链接集中在主笔记中，可以保持文献笔记的稳定性和主笔记的灵活性。

## 三、写入主笔记

### 3.1 找到直接引用位置

根据分析报告中「建议加入：」下第一个「[文件] 的 [具体章节/UID 附近]」定位：

```bash
# 1. 先用 outline-read 看目录结构
../outline-read/scripts/outline-read --dir raw PINN

# 2. 有 UID 参考点时，直接跳转
../outline-read/scripts/outline-read --dir raw --uid n3bg3i

# 3. 用 read 看周围原文，理解上下文和层级
read raw/PINN.md <start_line> <range>
```

**关键**：在插入前，必须充分阅读目标位置周围的原文，理解当前的层级结构、讨论脉络。新内容应自然延伸已有讨论的语境，而非突兀插入。

### 3.2 跨语境翻译

将文献笔记中有价值的内容写入主笔记时，不应直接复制原文。而应进行「跨语境翻译」：

- 文献笔记的内容存在于原论文的语境中（作者的问题意识、实验设定、论证逻辑）
- 主笔记的内容存在于目的手段链条的框架中（这个手段解决了什么子问题、属于哪个方案大类）
- 写入时应以主笔记的框架语言重新表述，使内容有机地融入该处的讨论

### 3.3 层级结构

主笔记采用 tab 缩进的大纲结构。插入新内容时：

- **新增顶层分支**：如果是一个全新的子问题讨论，从顶层（无缩进）开始新的一行 `* 主题`
- **在现有分支下扩展**：新行缩进层级 = 被扩展行的缩进层级 + 1
- **同级方案并列**：同一子问题下的不同方案保持相同缩进层级（OR 关系）

不要改动已有内容的层级结构，除非分析报告中明确提出了框架重构建议且用户同意。

### 3.4 引用文献笔记 UID

在写入的文本中引用文献笔记的具体内容行：

```markdown
* 上下文方案 ((_q6rk3a))ICM：改写为条件输入映射 (目标系统,s) ↦ r
```

`((_q6rk3a))` 引用文献笔记中的内容（下划线前缀表示文献笔记 UID）

**一引用一 UID 原则**：每个文献笔记的 UID 在主笔记中仅被引用一次。

### 3.5 追加其他引用位置

当一个技术手段服务于多个不同目的时（即同一文献笔记内容需要在主笔记的多个位置出现），不允许重复引用同一主笔记的 UID。
正确做法：例如，假设手段 X 同时服务于目的 A 和目的 B。

1. （3.1 已完成）在目的 A 的框架下，记录 X₁（手段 X 服务于目的 A 的具体方式），引用文献笔记 UID。
2. 为 X₁ 补充自己的主笔记 UID `{UID_X1}`（无下划线）。
3. 在 X₁ 的下层，注明该手段也服务于目的 B，引用目的 B 的框架位置（如 B 之前无 UID，可自行补充）：
	```markdown
	* 目的 A
		* 手段 X：…具体描述…((_litUID))；{UID_X1}
			* 该手段也可用于 ((UID_B))目的 B
	```
4. 在目的 B 的框架下，记录 X₂，内容可以很简短，直接链接到 X₁：
	```markdown
	* 目的 B；{UID_B}
		* 手段 X((UID_X1))
	```

**核心原则**：
- 主笔记 UID 可以被多次引用（与文献笔记 UID 不同）
- X₁ 是「主版本」，X₂ 是引用它的「次要记录」
- 主版本向次要记录的链接指向其所在框架位置（如 B），而非指向次要记录本身（如 X₂）

### 3.6 （如需要）分配自身 UID

主笔记中如果有内容行需要被其他位置引用，而之前未分配 UID，同样现场分配：

```markdown
* 上下文方案 ((_q6rk3a))ICM：改写为条件输入映射 (目标系统,s) ↦ r；{q6rk68}
```

这行内容可以通过 `((q6rk68))` 被主笔记的其他位置引用。

## 四、更新 keywd.md

如果新增的主笔记内容引入了新的关键概念，之前无相关记录，应在 `raw/keywd.md` 中添加关键词条目：

```
关键词 keyword：((UID))
```

- 关键词通常同时给出中英文
- UID 指向主笔记中最能代表该概念的那一行
- 若文件中已有类似概念，可追加到其附近，没有则放文件末尾即可

`keywd.md` 是扁平文件（无缩进），不需要用 outline-read 浏览，直接 `read` 或 `grep` 即可。

## 五、约束与注意事项

### 必须遵守

1. **不要改动已有的人工笔记**（包括日期格式、UID、措辞等），除非分析报告中明确建议且用户同意
2. **文献笔记中不放 `((UID))` 链接**（除极特殊情况）
3. **每个文献笔记 UID 在主笔记中仅引用一次**
4. **主笔记 UID 可多次引用**
5. **文献笔记 UID 用 `{_XXX}` 格式，主笔记 UID 用 `{XXX}` 格式**
6. **匹配现有的缩进风格**：用 tab 缩进，保持与周围内容一致的层级深度

### 建议遵循

- 写入前，主动检索笔记中是否已有相关讨论，避免重复或碎片化的记录
- 新内容尽量归入「系统分析层」的成熟框架（如 PINN.md 的 PDE 残差条目、aisc1.md 的本构关系学习条目），而非「方案设想层」的松散框架
- 不确定插入位置时，先保守（暂不写入），向用户说明情况
