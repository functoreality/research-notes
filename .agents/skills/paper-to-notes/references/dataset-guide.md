# 数据集状态判断指南

> 本文件是 SKILL.md 中「关于数据集」的详细说明。分析论文时按此指南判断数据集状态并完成验证，**报告中不得出现「需验证」「待确认」等字眼**。

## 数据集状态的五种基本情况

对每篇论文，首先判断属于以下哪种情况：

**情况 A：论文不涉及数据集。**
论文为纯理论、综述、或方法论框架，没有训练/测试任何模型。

**情况 B：论文全部使用现成公开数据集。**
所有实验数据来自已有的公开数据集（如 PDEBench、FNO 数据集等），论文未自建任何新数据。

**情况 C：论文涉及自建数据集，但未搜索到公开位置。**
论文描述了自己构造数据的方式，但已尽力搜索后未找到公开的代码仓库或数据下载位置。

**情况 D：论文未提及公开位置，但通过搜索找到了明确对应该论文的公开仓库。**
**情况 E：论文正文、附录或脚注中明确给出了代码仓库或数据下载链接。**

## 搜索策略

在判断情况 C/D 时需要主动搜索（可由子 agent 负责，并要求其读此文档）。搜索方式（按优先级）：

1. 检查论文内是否包含代码/数据链接
2. 搜索引擎搜索：`论文标题 GitHub`、`论文方法名 GitHub`、`论文方法名 HuggingFace`
3. **搜索引擎选择**：优先 Google；若不可用，换 Bing 或其他可用引擎
4. **GitHub/Hugging Face**：很多数据集发布在 Hugging Face 上（`huggingface.co/...`），搜索时应包含
5. **镜像站**（中国大陆网络环境下）：GitHub 可尝试 `bgithub.xyz`，Hugging Face 可尝试 `hf-mirror.com`
6. 检查作者主页或个人网站是否有链接

## 验证要求（情况 D 和 E）

找到公开位置后，**必须实际访问并完成以下两项独立验证**（可由子 agent 负责，并要求其读此文档），再输出报告。

### 两个独立验证维度

| 维度 | 问题 | 验证方式 |
|------|------|---------|
| **公开数据集文件** | 该位置有可直接获取的数据集文件？ | 查找 .h5、.npy、.npz、.mat、.pt、.zip、.tar.gz 等数据文件。数据集可能不在仓库内，而是外部下载链接（见 README、release 页面） |
| **数据生成代码** | 该位置是否包含数据生成脚本？ | 检查仓库中是否有数据生成相关的脚本（如 `generate_data.py`、`data_gen/` 目录、README 中描述的生成命令等） |

两个维度独立判断，互不排斥。一个仓库可以同时有数据集文件和生成代码，也可以仅有其中之一，也可以都没有。

### 验证结果分类（统一适用于 D 和 E）

对于一个找到的公开位置，按其满足的维度组合归类：

| 分类 | 有数据集文件 | 有生成代码 | 是否值得记录 |
|------|:-----------:|:---------:|:-----------:|
| 类型 1 | ✓ | ✓ 或 ✗ | **值得**（满足「自己构造 + 公开发布」） |
| 类型 2 | ✗ | ✓ | **值得**（有生成代码等价于数据集可重现） |
| 类型 3 | ✗ | ✗ | **不值得** |

## 报告的「数据集」部分要求

报告中必须明确陈述：

1. 属于情况 A/B/C/D/E 中的哪一种
2. 对 D 或 E，写明公开位置的 URL
3. 对 D 或 E，逐一陈述两个维度的验证结果（不得用「需验证」替代）
4. 若值得记录，可简要描述数据集内容

**报告示例**：

- 情况 A：「论文不涉及数据集。」
- 情况 B：「论文全部使用现成公开数据集（PDEBench），无自建数据。」
- 情况 C：「论文涉及自建数据集，但论文未提及公开位置，经搜索（Google "论文标题 GitHub"、arXiv 页面等）未找到对应仓库或数据下载链接，不满足记录条件。」
- 情况 D 类型 1：「论文未提及公开位置，但经搜索在 GitHub 找到对应仓库 `https://github.com/xxx/yyy`。经验证，该仓库包含可下载的数据集文件（.h5 格式），且包含数据生成代码，满足记录条件。」
- 情况 D 类型 2：「论文未提及公开位置，但经搜索在 Hugging Face 找到 `https://huggingface.co/datasets/xxx`。
  经验证，该位置不包含预生成的数据集文件，但包含数据生成代码，满足记录条件。」
- 情况 E 类型 3：「论文提及代码仓库 `https://github.com/xxx/yyy`。经验证，该仓库既不包含数据集文件也不包含数据生成代码，不满足记录条件。」

## 记录位置

值得记录的数据集主要记录在 `numeric.md`。该文件中数据集条目分布在多个位置：有些集中在特定数据集节，有些分散在各方程类型的对应位置。
找入口：文件内搜「数据集」，命中后沿周围层级结构定位到合适的子节。浏览建议用 outline-read。
