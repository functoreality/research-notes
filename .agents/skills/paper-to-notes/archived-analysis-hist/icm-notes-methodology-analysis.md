## 二、核心方法论特征

### 2.1 组织原则：「目的」优先于「形式」

**修改前（PINN.md）**：
```
loss 可能性（通常无监督）
  ├── PDE residual loss（PINN 狭义）
  ├── Galerkin
  ├── Ritz 变分
  ├── FVM
  └── SDE
```
组织维度：**手段的类型**（你用什么数学形式来表达 loss）

**修改后（PINN.md）**：
```
PDE 残差 {n3bg3i}
  ├── 目标功能，用于判断什么的好坏
  │   ├── 针对解
  │   ├── 针对方程（包括本构关系）
  │   └── 同时针对解和方程
  ├── 非评判目的：作系统描述 ← ICM 的归宿
  │   └── 方程系数作为网络输入，表达目标物理系统
  ├── PDE 形式及其变种（原内容，归入此处）
  ├── 选择—维数、光滑性
  └── 混用—按子方程 / 按训练阶段
```
组织维度：**PDE 残差被用来做什么**（评判解的质量？评判方程的正确性？还是描述系统本身？）

**方法论含义**：同一个数学对象（PDE 残差），因使用目的不同，归属到不同的框架分支。这不是「按类型分类」，而是「按它在因果链中所处的位置分类」。

### 2.2 发现新范畴的能力

ICM 论文的核心技术贡献之一是：将 PDE 残差（传统上仅作为 loss）重新定位为「系统表示」。用户在笔记中为这一用法创造了新范畴：

```
非评判目的：作系统描述
  ├── 方程形式，可为数值离散后所得代数方程
  ├── 离散结果不全用：可排除观测信息不足的局部
  ├── 可用场景：上下文建模 ICM
  └── 相关：仿TRIZ原理-替身
```

**关键洞察**：这一范畴的创建不是因为「ICM 用了一种新类型的方程」，而是因为「方程被用于了一个新目的」。
前者是分类学思维，后者是目的手段链思维。
分类学思维下，ICM 的 loss 设计会被归入「PDE residual loss」的某个子类；目的手段链思维下，ICM 开辟了一个之前不存在的顶层范畴。

### 2.3 系统化的目的手段链拆解

`aisc1.md` 中新增的内容展现了最完整的目的手段链：

```
目标：构建映射 目标系统 ↦ s ↦ r（特定输入输出变换）

├── 常规方案：外层映射基于训练
│   └── s ↦ r 用 NN 直接表示
│       └── 只需完成 构建映射 目标系统 ↦ θ
│           ├── 要素：loss
│           └── 要素：优化算法
│
└── 上下文方案 ICM：改写为条件输入映射 (目标系统,s) ↦ r
    ├── 要素—目标系统 改为可作网络输入的形式
    │   └── 方案：系统局部满足方程，离散代数方程系数作为系统的表示
    ├── 要素—映射表示
    │   └── 方案：NN 直接表示
    └── 要素—训练
        └── 资源需求：需预先准备一系列目标系统
```

这个链条的特点：
- **从同一顶层目标出发**分叉为两种方案，而不是分别从两个目标出发
- **每个要素标注了「可用资源」**（如「系统局部满足方程」是上下文方案的可用资源）
- **方案之间不是「哪一种更好」**，而是「各自依赖什么资源、适合什么场景」
- **链条可以在任意环节分叉**，例如「定义 loss func」这个子问题又可以按资源（基于系统响应 vs 基于局部方程）再分出两个子方案

### 2.4 「手段一般化」的倾向

多处修改体现了将具体技术点向上抽象为一般原则的习惯：

| 具体技术点 | 被一般化为 | 出现在 |
|-----------|----------|--------|
| ICM 的 DIC→三角网格插值 | 「粗化适配训练模式，均匀细网格插值到三角粗网格」 | `PINN.md` coordLoss |
| ICM 的不可靠节点排除 | 「局部弱化：若某局部信息不足……空间汇总得整体 loss 时可对其降权或直接无视」 | `PINN.md` coordLoss |
| ICM 的方程系数作输入 | 「物理系统（如 PDE 本构关系）的替身」 | `triz4ml.md` |
| ICM 的 t-SNE 分析 | 「表征与任务特征相关性评估」的一般框架 | `metaL.md`, `NNarch.md` |
| ICM 的 loss 设计 | 「参与组成的超系统行为符合预期」 | `data.md` |

**方法论含义**：用户不是把 ICM 当作一个孤立的论文条目来记录，而是将其各个技术要素拆解后，分别归入笔记系统中已有的（或为此新建的）一般性框架。
这保证了笔记的**可检索性**——将来遇到类似技术时，不管来自哪个领域，都能在同一个框架下找到。

## 三、与 Sisyphus 之前分析的关键差异

### 3.1 差异一：定位逻辑

**Sisyphus 的方式**：识别 ICM 中「笔记里没有的话题」，然后建议「这个话题可以加在文件 X 的某个位置」。判断标准是**话题名称的匹配**。

**用户的方式**：识别 ICM 中每个技术要素所解决的**问题**，然后在笔记中找到（或创建）以该问题为组织维度的框架，将技术要素作为该问题的**一种解决方案**加入。判断标准是**因果链中环节的匹配**。

具体例证：
- Sisyphus 说：「physics-informed tokenization 在笔记中缺失，可以加在 NOarch.md 输入层」
- 用户的实际做法：「PDE 残差」这个顶层条目下新增「非评判目的：作系统描述」范畴，ICM 的 token 化（方程系数作输入）作为该范畴下的一个具体手段。
  同时 coordLoss 部分新增「预处理-改离散」场景，ICM 的 DIC→网格插值作为场景案例。

用户没有去 `NOarch.md` 讨论 token 化，因为在用户看来，ICM 的 token 化**本质上不是关于 token 化策略的问题，而是关于「PDE 残差可以用于什么目的」的问题**。token 化只是实现手段，不是问题本身。

### 3.2 差异二：分解粒度

**Sisyphus 的方式**：以「技术贡献」为分析单元。ICM 有四个技术贡献 → 对应四个建议补充位置。

**用户的方式**：将每个技术贡献进一步拆解为多个独立的「问题-方案」对，各自归入不同框架。
- ICM 的「无监督训练」→ 归入 loss 设计框架（`PINN.md`），作为基于局部方程的 loss 方案
- ICM 的「方程系数作输入」→ 归入 PDE 残差的目的分类（`PINN.md`），作为系统描述用途；同时归入 TRIZ 替身原理（`triz4ml.md`）
- ICM 的「DIC 预处理」→ 归入数值微分的预处理框架（`PINN.md` coordLoss），作为改离散场景
- ICM 的「t-SNE 分析」→ 归入表征质量评估框架（`metaL.md`, `NNarch.md`）
- ICM 的「跨材料泛化」→ 归入本构关系学习方案对比（`aisc1.md`），作为上下文方案 vs 常规方案

一个论文被拆成 5+ 个独立要素，各自归入不同的框架。这保证了每个要素在笔记中有**唯一的、由问题驱动的检索路径**。

### 3.3 差异三：抽象层级

**Sisyphus 的方式**：倾向于在「话题」层面操作。「这里有一个关于 X 的新方法，可以补充到 X 主题的文件中。」

**用户的方式**：在每个要素被加入时，同时进行「向上抽象」——将具体技术提炼为一般原则，并将该原则也纳入笔记。例如：
- ICM 的具体做法「方程系数作输入」→ 抽象为「PDE 残差的非评判目的：作系统描述」
- ICM 的具体做法「DIC 插值到三角网格」→ 抽象为「预处理-改离散-粗化适配训练模式」
- ICM 的具体做法「排除不可靠节点」→ 抽象为「局部弱化：信息不足时降权或无视」

抽象后的原则成为笔记的一级公民，而 ICM 作为该原则的一个实例被引用。这保证了未来遇到类似原则的新工作时，不需要再次从零分析。

### 3.4 差异四：资源与约束的显式标注

**Sisyphus 的方式**：在目的手段链条分析时标注了资源和约束，但在笔记补充建议中未体现这一维度。

**用户的方式**：在笔记中显式标注资源条件。例如 `aisc1.md` 中：
- 「资源需求，需预先准备一系列目标系统，由于此时目标系统为 NN 而非算法的输入」
- 「系统局部满足方程（可用资源）」
- 「数值模拟程序（以本构关系为输入）」

这些标注使得笔记不仅是「做了什么」的记录，更是「在什么条件下可以做」的知识库。

### 3.5 差异五：废弃而非覆盖——成熟度分层

**Sisyphus 的方式**：倾向于「在现有内容旁边加新内容」。

**用户的方式**：当旧内容的组织框架不再适用时，会**显式标注废弃**。
例如 `largeNN.md` 的「PDE 大模型可能性？」被标注为「（废弃）」。
但「废弃」的含义不仅是声明过时——更深层的是，旧内容代表**思想不成熟阶段的方案设想**（enumerating possible technical routes），
而新框架代表**系统化的问题分析**（identifying the core bottleneck and organizing around it）。

具体而言，旧 `largeNN.md` 中「PDE 大模型可能性？」的组织方式是枚举各种可能的任务定义、输入模态、训练策略——这是「可能怎么做」的发散探索。
新框架（`NOarch.md:322` 及其下属 `:369`）将问题聚焦为：**构造 PDE 基础模型的关键难点是让一个模型处理大量不同的 PDE → 核心子问题是「如何实现对 PDE 形式的泛化」**。
这是「核心问题是什么 → 如何解决」的收敛分析。

两者的区别不是「旧内容错了」，而是「旧内容的组织层级不对」——方案设想应该从属于问题分析，而不是替代问题分析。标注废弃 = 承认那段内容反映的是分析框架尚不成熟阶段的中间产物。

### 3.6 差异六：文献笔记→主笔记的迁移有明确标准

**Sisyphus 的理解**（第一版分析中）：「文献笔记保存完整论文信息，主笔记提取可迁移的原则」——这基本正确，但缺少迁移标准的细化。

**用户的实际标准**——类似专利三要素：

1. **新颖性**：主笔记现有框架中不包含类似的做法。如果主笔记已有同类手段的讨论，文献笔记中的具体实现只是已有框架的又一个实例，无需迁移。
2. **实用性**：该技术要素确实有用，且不限于当前问题的场景，可以迁移解决更一般框架下的问题。
3. **非平凡性**：如果该技术要素本来就容易想到（如标准组件的常规组合），不是所有时候都有必要特意记录到主笔记。

**具体例证**：ICM 的 token 处理网络架构（subtoken 自注意力 → pooling → token 间自注意力 → 交叉注意力到 query）没有进入主笔记。
用户对此的判据是：「这个基本上就是很一般的思路」——只是标准 attention 机制的常规组合，不具有非平凡性。
文献笔记中对它有记录，但仅为「帮助我重新看这篇文献笔记时知道这篇论文在干什么」——属于理解论文细节的层面，不属于可迁移的原则。

这解释了为什么文献笔记篇幅很长（AISClit9.md 88行）但主笔记只吸收了特定几个要素：每个要素都通过了新颖性、实用性、非平凡性的筛选。

## 四、方法论溯源：TRIZ 框架在 ICM 笔记修改中的体现

用户的笔记整理方法论根植于现代 TRIZ 理论，特别是「目的手段链条」和「因果链分析」两套工具。以下将 ICM 笔记修改中的关键操作逐一对应到 TRIZ 框架中的具体原则。

### 4.1 「目的手段链条」vs「因果链分析」的适用场景

来自 `perspective/triz.md:272-278`：

> 因果链分析 vs 目的手段链条：使用场景，前者 判别器分解（问题分析），后者 解决方案生成（系统设计）

在 ICM 的场合：
- **因果链分析** 适用于「为什么传统 modeling-by-optimization 不够好」→ ICM 论文列出了三个瓶颈（未能利用物理规律、无法 scale、优化范式本身），这正是因果链分析的结果。
  但用户没有将此纳入笔记，因为笔记关注的是「我们有什么方案可用」，而非「为什么旧方案不好」。
- **目的手段链条** 适用于「如何实现本构关系的跨材料泛化」→ 这正是 `aisc1.md` 新增内容的核心：从同一顶层目的出发，分叉为常规方案和上下文方案。

### 4.2 目的手段链条的节点类型体系

来自 `perspective/triz.md:68-113`，目的手段链条区分三种节点类型：

| 节点类型 | TRIZ 定义 | ICM 笔记中的对应 |
|---------|----------|----------------|
| **属性状态** | 使现有对象产生新行为 | `aisc1.md`：「构建映射 目标系统 ↦ s ↦ r」—— 这是期望达成的属性状态 |
| **科学效应**（手段大类） | 输入输出变换，抽象大类下有多种具体方案（OR 关系） | `aisc1.md`：「常规方案 vs 上下文方案」—— 两种方案大类，OR 关系 |
| **带性质的新对象**（手段细化） | 产出具有某性质的对象，子结构 AND 关系 | `aisc1.md`：上下文方案的三个要素（系统表示、映射表示、训练）—— AND 关系，缺一不可 |

这个节点类型体系解释了为什么 `aisc1.md` 中同一层级既有 OR 分叉（常规 vs 上下文），又有 AND 并列（系统表示 AND 映射表示 AND 训练）——它们在目的手段链条中属于不同的展开方式。

### 4.3 「属性状态」展开的两种方式

来自 `perspective/triz.md:76-93`：

- **偏向实然因果拆分**（封闭系统推演）：「手段—导致它的属性因素」—— 类似因果链分析的静态版本。`aisc1.md` 中「定义 loss func」的展开属于此类：loss 能反映差异 ← 基于系统响应 OR 基于局部方程。
- **偏向开放系统提方案**（引入外部资源）：「手段—科学效应」「手段—具有某性质的新对象」—— 打破封闭、引入新的组件或机制。
  `aisc1.md` 中「目标系统改为可作网络输入的形式 ← 系统局部满足方程」属于此类——引入了方程系数这一外部资源来替代直接观测。

这解释了为什么 `aisc1.md` 中某些子问题展开到方案层就停止（因为已进入开放系统的「引入新对象」层，方案的进一步细化属于具体实现），
而另一些子问题持续展开到因果层（因为仍在封闭系统内，可以按必要条件继续拆分）。

### 4.4 展开完备性：避免跳步与保证宽度

来自 `perspective/triz.md:73-75`：

> 原则：尽量每层拆充要……需逐步展开、避免跳步，且保证宽度、单层完备

ICM 笔记修改中体现：
- **避免跳步**：`aisc1.md` 的链条没有从「构建映射」直接跳到「用 ICM」，而是经过了「目标系统如何表示」「映射如何表示」「如何训练」三个中间层。每一层都是上一层的必要条件（充要分解）。
- **保证宽度**：在「定义 loss func」这一层，同时列出了「基于系统响应」和「基于局部满足方程」两种方案（OR 宽度），而非只记录 ICM 所用的那种。在「方案大类比」层，同时列出了「常规方案」和「上下文方案」。

Sisyphus 之前的分析之所以不够深入，正是因为跳过了中间层——直接从「ICM 的 token 化」跳到「建议加在 NOarch.md」，而没有问：token 化服务于什么目的？这个目的在目的手段链的哪一层？

### 4.5 PINN.md 重组：从「手段分类」到「目的分类」

`perspective/triz.md:45-52` 区分了目的手段链条的多种用途，其中「开放目的、开放手段：领域话题关系」对应笔记中框架性条目的组织：

> 领域话题关系 eg. 笔记场景目的，科研-AISC框架

用户对 PINN.md 的重组正是将「PDE 残差」从「手段名目下的子条目」提升为「按目的组织的顶层条目」。
原来的组织方式是：在 `PINN%`（一个手段大类）下，按 loss 的数学形式（PINN/Galerkin/Ritz…）分类——这是**手段分类**。
新的组织方式是：在 `PDE 残差`（一个独立顶层条目）下，按「用来做什么」（评判解/评判方程/描述系统）分类——这是**目的分类**。

这个转变对应 TRIZ 中的一个深层洞察：**同一个科学效应（PDE 残差）可以服务于多个不同的属性状态（评判质量 vs 描述系统）**。
按手段分类只能看到「有哪些手段可用」，按目的分类才能看到「每个手段可以服务于哪些目的」——后者对创新设计更有价值，因为它允许你将已有手段应用到新的目的上。

### 4.6 因果链分析的节点表述原则

来自 `perspective/triz.md:286-296`：

> 避免目的节点：各节点尽量按状态（状态X/发生X）表述，避免目的（避免X）表述
> 动力、目的因区分：状态表述 发生A ← 发生B ← 发生C 按动力因展开

这一原则在 ICM 笔记中的体现较为隐含，但可以观察到：`aisc1.md` 中的链条表述使用的都是状态/动力因语言（「系统局部满足方程」「离散代数方程系数作为系统的表示」），而非目的因语言（「为了避免重训，我们使用 ICM」）。
这保证了链条的每个环节都可以被独立验证——「这个环节是否确实发生了？」而非「这个环节是否有助于达成目的？」

### 4.7 文献笔记→主笔记的迁移与手段展开宽度

`perspective/triz.md:237` 提到「手段展开宽度，列出尽可能多的手段（or 层级）」。在笔记整理中，这意味着主笔记应追求手段展开的完备性（列出所有已知方案大类），而文献笔记中可以只有单个具体方案。

ICM 的 attention 架构没有进入主笔记，不仅因为「非平凡性」不足，更因为它在目的手段链条中的位置过深（已经到了第四个展开层级以下），属于具体实现细节而非方案大类。主笔记应当覆盖到「方案大类」层级，而将「具体实现」留在文献笔记。

### 4.8 对 Sisyphus 的额外启示

TRIZ 框架揭示了 Sisyphus 之前分析中一个之前未被识别的盲区：

**Sisyphus 混淆了「手段」和「目的」的层级**。
当我建议「physics-informed tokenization 加在 NOarch.md 输入层」时，我是把 ICM 的一个手段（方程系数 token 化）匹配到了笔记中另一个手段（空间 token 化）所在的位置。
但实际上，ICM 的这个手段服务于一个**新的目的**（用方程系数表示物理系统），而这个新目的应该在「目的分类」的框架下（PDE 残差的用途）而非「手段分类」的框架下（token 化的方式）被记录。

这意味着 Sisyphus 未来在分析论文时，需要先判断：论文中的技术要素是「已有目的的新手段」还是「已有手段的新目的」。前者应在手段分类下添加新条目；后者应扩展目的分类、创建新范畴。

## 五、用户笔记方法论的总结性描述

基于以上分析（包括差异对比和 TRIZ 框架溯源），用户整理笔记的核心方法论可以概括为以下几个原则：

### 原则 1：目的驱动分类
笔记的组织维度是「这个数学对象/技术手段被用来解决什么问题」，而非「这个数学对象/技术手段本身是什么类型」。

### 原则 2：系统化因果链拆解
遇到任何技术工作时，将其拆解为：
```
顶层目标
  └── 子问题 1
  │   ├── 可用资源 A
  │   ├── 方案 1a（依赖资源 A，受约束 X）
  │   └── 方案 1b（依赖资源 B，受约束 Y）
  └── 子问题 2
      └── ...
```
每个方案在笔记中记录时，标注其依赖的资源和面对的约束。

### 原则 3：要素级而非论文级记录
一篇论文的多个技术贡献被拆开，各自归入笔记中相应的因果链环节。不保留「论文 X 做了什么」的完整叙事，而是将论文的各要素分别融入知识框架。

### 原则 4：向上抽象
每个具体技术在被记录的同时，提取其背后的一般性原则，并将该原则也纳入笔记。具体技术作为原则的实例被引用。

### 原则 5：成熟度分层
区分「方案设想」和「系统化问题分析」两种不同的笔记组织层级。
方案设想（如枚举各种可能的输入模态、训练策略）是分析框架尚不成熟阶段的中间产物；系统化问题分析（如聚焦核心瓶颈、按子问题展开）是框架成熟后的组织方式。
前者可以标注废弃并保留作为历史痕迹，但其内容不应被当作当前分析框架的出发点。

### 原则 6：迁移过滤
从文献笔记到主笔记的迁移需通过三要素筛选：新颖性（主笔记现有框架不包含）、实用性（可迁移到更一般的问题）、非平凡性（不是显然的标准组件组合）。不满足的要素保留在文献笔记层，仅服务于「理解论文细节」的目的。

### 原则 7：概念宽泛度由框架定位决定
笔记中借用的概念（如 TRIZ 替身）刻意保持宽泛，因其目标是为 ML 领域建立一个对标 TRIZ 的体系。概念的宽泛度服务于框架的包容性目标，不应过早收紧。

## 六、Sisyphus 需要改进的方向

### 5.1 从「话题匹配」转向「问题匹配」

在评估一篇论文是否值得加入笔记时，不应问「笔记中是否有关于这个主题的讨论」，而应问「论文解决了什么（子）问题？笔记中是否有以该（子）问题为组织维度的框架？」

这要求 Sisyphus 在分析论文时，先完成目的手段链条的拆解，再逐一检查笔记在链条各环节的覆盖情况。

### 5.2 从「论文级」转向「要素级」

一篇论文不应作为一个整体被记录，而应按其技术要素分别归入不同框架。这要求 Sisyphus 在分析时识别出论文中的独立技术要素（通常 3-8 个），并为每个要素找到（或建议创建）合适的框架归属。

### 5.3 建立「目的分类」的意识

在阅读笔记时，要识别出笔记的组织维度是「按目的分类」而非「按形式分类」。
在建议补充位置时，应优先考虑「这个技术要素解决了什么问题 → 笔记中哪个部分是按这个问题组织的」，而非「这个技术要素叫什么名字 → 笔记中哪个文件讨论了这个名字的话题」。

### 5.4 资源与约束的标注

在记录任何技术方案时，应同时标注其依赖的资源和面临的约束。这可以从论文的方法部分提取。

### 5.5 向上抽象的主动性

在将具体技术归入框架时，如果该技术揭示了现有框架中缺失的维度，应主动建议扩展框架（创建新范畴），而非仅仅在现有范畴下添加条目。

### 5.6 识别框架的成熟度级别

笔记中不同部分的框架成熟度不同。在分析时应注意区分：
- **方案设想层**（如旧 `largeNN.md`）：枚举可能的技术路线，组织松散，偏发散探索
- **系统分析层**（如新 `PINN.md` PDE 残差部分）：聚焦核心问题，按目的手段链展开，偏收敛分析

当被要求「补充笔记」时，不应将方案设想层的内容当作权威框架来匹配新内容，而应优先寻找或协助建立系统分析层的框架。

### 5.7 迁移标准意识

在建议将论文内容加入主笔记时，应评估其是否满足三要素标准（新颖性、实用性、非平凡性）。纯粹为了「知道这篇论文做了什么」的内容应建议留在文献笔记层。

### 5.8 区分「已有目的的新手段」vs「已有手段的新目的」

这是 TRIZ 框架揭示的一个关键盲区。在分析论文的技术要素时，先判断：

- **已有目的的新手段**：该技术要素服务于笔记中已识别的某个目的（如「评判解的精度」），但使用了一种新的手段。应归入该目的下的手段分支。
- **已有手段的新目的**：该技术要素使用了一个笔记中已知的手段（如「PDE 残差」），但服务于一个新的目的（如「描述物理系统」）。应扩展目的分类、创建新范畴，而非在手段分类下添加条目。

Sisyphus 之前将 ICM 的 token 化归入「token 化策略」（手段分类），但 ICM 实际上是在用方程系数做一件新的事情（系统表示）。
正确做法是先识别出「系统表示」这个新目的，然后在目的框架下记录它。

### 5.9 注意展开层级：主笔记覆盖到「方案大类」，文献笔记覆盖到「具体实现」

目的手段链条的展开可以很深。
主笔记的组织应聚焦于较浅的层级（方案大类、OR 分叉），而「具体实现细节」（如特定的 attention 架构组合）属于文献笔记层。
在建议补充位置时，应评估该要素在目的手段链中所处的层级——过深的层级不应进入主笔记。

## 七、已确认的问题

以下三个问题在第一版分析中被标记为「存疑」，经用户澄清后确认如下。

### 6.1 `largeNN.md` 废弃的本质

旧 `largeNN.md` 中「PDE 大模型可能性？」一节被标注废弃，原因是该内容属于**思想不成熟阶段的方案设想**（枚举各种任务定义、输入模态、训练策略），而非系统化的问题分析。
替代框架为 `NOarch.md:322`（及其下属 `:369`），其分析逻辑为：

> 构造 PDE 基础模型的关键难点 = 让一个模型处理大量不同的 PDE
> → 核心子问题 = 「如何实现对 PDE 形式的泛化」
> → 围绕这一核心子问题展开架构设计（而非枚举各种可能的输入格式）

这不意味着旧内容「错了」，而是它的组织层级不对。方案设想应该从属于问题分析的结果，而非替代问题分析。

### 6.2 「替身」概念的宽泛性

用户在 `triz4ml.md` 中将 ICM 的「方程系数作系统表示」归入 TRIZ 替身原理。该概念被刻意保持宽泛，原因有二：
- TRIZ 本身的替身概念就是宽泛的（如标准解中「用投影替代直接测量」「用一个对象拟合后再测量」、曹冲称象）
- 用户的目标是为 ML 领域建立一个对标 TRIZ 的体系，概念宽泛度服务于框架的包容性

因此，替身概念不需要收紧定义。任何「用一个可计算/可操作的对象替代一个难以直接获取/操作的目标对象」都符合替身的宽泛含义。在分析时不需要纠结分类的精确边界。

### 6.3 文献笔记→主笔记的迁移标准

两层的关系确实如第一版分析所述：「文献笔记保存完整论文信息，主笔记提取可迁移的原则」。迁移的筛选标准类似专利三要素：

| 标准 | 含义 | ICM 示例 |
|------|------|---------|
| **新颖性** | 主笔记现有框架不包含类似做法 | 方程系数作系统表示（满足，创建了新范畴） |
| **实用性** | 不限于当前问题，可迁移到更一般框架 | DIC→网格插值（满足，归入预处理的一般框架） |
| **非平凡性** | 不是标准组件的显然组合 | ICM 的 attention 架构（不满足，仅记录在文献笔记） |

不满足三要素的内容保留在文献笔记层，服务于「重新看这篇论文时知道它在干什么」的需求。不存在「文献笔记中的内容必须同步到主笔记」的强制约定。
